# 4.26.0 发票批量入账

> 口径时间：2026-11-25。版本 `4.26.0`（上一版 `4.25.0` 银行流水批量匹配）。

## 一、为什么做这个

4.25.0 之前，托管台已经能配对银行流水、确认收支归因、交接税务核对包、执行企业月结，但发票夹一直停在“识别—确认—归档”的文件状态。费用票确认了，账上却没有凭证；用户还要拿发票号去总账里手工补一张分录。

这轮补的不是新入口，而是把“已确认费用票”变成真实的已过账凭证：`invoice_post`。它只处理费用票，不碰采购应付，不碰收入票，也不改发票识别结果。

## 二、动作契约

- 动作键：`invoice_post`；默认 `manual`，沿用 `manual / assist / auto` 三档。
- 范围：只扫当前账期（`YYYY-MM`）内 `kind=expense`、`status=confirmed`、且没有入账记录的发票。
- 默认三科：费用 `6602` 管理费用、进项税 `2203` 应交税费、应付 `2202` 应付账款；可在卡片上改成其他启用科目。
- 科目类型校验：费用科目必须是 `expense`；进项税科目必须是 `asset/liability`；应付科目必须是 `liability/asset/equity`。编码不存在或已停用直接阻断。
- 默认本批价税合计上限 `50000` 元，`0` 表示不限；单次最多 100 张，超过部分留在 `pending`，不静默丢弃。
- 逐张校验：开票日期在账期内、价税合计 > 0、税额不超过价税合计。
- 采购应付去重：`payables.invoice_no` 已登记同一发票号的，跳过并给出原因；采购应付审批会写总账，不能重复入账。
- 本批合计超过上限时，`auto` 也回落 `awaiting`，必须再确认一次。
- 一张发票一张凭证：借费用（不含税金额）、借进项税、贷应付（价税合计）；税额为 0 时不写进项税行。
- 执行走 `invoice_post_batch`：单事务原子写，任一张发票在计划后状态、日期、金额或税额变化，整批回滚。
- 幂等：`invoice_postings` 以 `(user_id, invoice_id)` 为主键，重复执行不会生成第二张凭证。
- 期间：写凭证前确认账期已打开；账期缺失或已关闭直接阻断，不新建期间。
- 溯源：每张发票写 `record_provenance("invoice_post", "invoice", ...)`，记录凭证号、金额、税额与账期；凭证本身可在总账反冲。
- `run-all` 顺序改为：发票入账 → 银行流水匹配 → 归因确认 → 企业月结 → 税务交接。先把费用票落账，再做资金与分类收尾。

## 三、数据与演示

- 新增 `backend/app/db/invoice_postings.py`：
  - `invoice_posted_ids(user_id, ids)` 查询幂等集合；
  - `invoice_numbers_in_payables(tenant_id, numbers)` 查询采购应付已登记发票号；
  - `invoice_post_batch(tenant_id, user_id, items, period)` 单事务校验、写凭证、写入账表。
- 新增表 `invoice_postings(user_id, invoice_id, tenant_id, entry_id, period, amount_cents, tax_cents, created_at)`，主键 `(user_id, invoice_id)`。
- `connect_invoices.py` 新增 `list_invoices_for_post(period, limit=200)`，只返回账期内已确认且未入账的费用票；`get_invoice` / `list_invoices` 左联入账表返回 `posted` 0/1。
- 演示重置先清理 `source='invoice'` 的旧凭证与凭证行，再清 `invoice_postings` 与 `invoices`，避免重置一次就多一批无法追溯的旧发票凭证。
- 演示种子两张已确认费用票：
  - `inv_demo_4260_1`，办公耗材，价税合计 ¥113，税 ¥13，日期 `2026-11-05`，销方“潮州云仓商贸有限公司”；
  - `inv_demo_4260_2`，快递月结，¥220，税 0，日期 `2026-11-08`，销方“顺丰速运有限公司”。
- 预期：2 张、合计 ¥333；凭证一借 `6602` ¥100、借 `2203` ¥13、贷 `2202` ¥113；凭证二借 `6602` ¥220、贷 `2202` ¥220。

## 四、前端

- 托管台从四张动作卡扩到五张：发票入账、银行匹配、归因、月结、税务；桌面端前四张两列、发票卡独占整行，移动端单列。
- 发票卡可配费用/进项税/应付三科与本批价税合计上限；默认 `6602 / 2203 / 2202 / 50000`。
- 结果区区分：手动只出计划、无候选阻断、超阈值待确认、执行成功；显示本批价税合计、待入账张数与已入账张数。
- 发票夹列表：`parsed` 显示“确认”按钮，调用 `PATCH /api/connect/invoices/{id}` 置 `confirmed`；`confirmed` 显示“已确认”，有入账记录显示“已入账”。
- 中英文案同步；页面边界补上“发票批量入账”；自助入口增加发票夹确认与托管入账。

## 六、本轮不做

- 不做收入票、增值税专用发票认证、税局发票查验；只处理已确认的费用票。
- 不做发票与采购订单/入库单的三方匹配；同号已在采购应付登记的直接跳过。
- 不自动拆税率、不按商品行拆分科目；一张发票一张凭证，科目由用户在卡片上指定。
- 平台账单对账仍缺文件收件箱、平台导出列映射与商户授权，不拿上传预览冒充自动对账。
- 不接税局直连、不代划款、不出法定审计意见。
