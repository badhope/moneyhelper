# 4.23.0 产品差异化备忘：把“自动化”做成可托管、可退出、可举证

> 这不是功能清单，而是判断标准：以后每加一个能力，先问它是否让用户少点一次、是否保留手动出口、是否留下可复核证据。

## 一、差异化不在“AI 会聊天”，在“财务动作能托管”

市面上有三类产品：

1. 记账/报表工具：能算，但跨系统动作仍要人搬。
2. RPA/自动化工具：能点，但规则散落在流程里，出错后难举证。
3. 通用 AI 助手：能给建议，但不接管账、不落决策、不对结果负责。

Moneyhelper 的差异点是把三者接在一个闭环里：**数据 → 计划 → 执行 → 证据**。

- 数据来自本机账本、凭证、税务包、平台账单。
- 计划由确定性计算给出金额、通道、阻断项，模型只负责解释。
- 执行复用已有真实链路（SMTP、签名网关、月结工作流），不是演示按钮。
- 证据落决策台账、投递台账、审计事件；重复执行有幂等键。

所以“AI 接管”不是换一个聊天框，而是把原来要人点的步骤变成可预设、可审计的策略对象。

## 二、不可替代性来自“断开就丢证据”

单点能力都容易被替代：记账有成熟软件，报税有代账，电商后台有官方报表。难替代的是把这几段接起来，并且在每一步留下同一套证据：

- 税务核对包生成后，能直接交给已就绪通道；重复交有幂等键，不会重复发。
- 月结与税务交接有固定顺序，不会在关账前生成税包。
- 每次自动执行都写决策：谁、什么规则、金额、通道、结果、阻断原因。
- 失败不吞：外部投递失败写审计，托管失败记 `failed`，不伪装成功。
- 数据留在本地 SQLite，不把敏感财税数据交给第三方子智能体。

对用户来说，换掉这套系统不只是换界面，而是丢掉“为什么当时自动执行了、执行到哪、对端有没有收”的连续记录。

## 三、傻瓜化不是少功能，是少选择

这一版把“傻瓜化”落成三个具体约束：

1. **默认只评估**：新动作默认 `manual`，先看计划，不擅自执行。
2. **一次设置长期生效**：模式、通道、金额阈值按动作保存，不用每次重配。
3. **只保留一个确认点**：`assist` 只在执行前停一次；`auto` 在规则内不停；超阈值/缺通道才停。

同时保留完整自由度：

- 想手动，就用手动模式或原有分步页面，所有接口与页面都在。
- 想半自动，用助理模式，看完计划点一次。
- 想全自动，用自动模式并预设阈值；不确定就先“只评估，不执行”。

## 四、场景推进顺序

1. **税务先做深**：税务核对包已经能生成、留档、真实投递；这版把通道、金额阈值、确认模式做成规则，并把月结排在税包之前。
2. **电商做配套**：先做确定性经营测算，帮用户判断“到底赚不赚钱、推广最多能花多少”；再通过开放平台/MCP 读订单与账单，授权后只读，不代运营、不代下单。
3. **内容社区暂停**：没有平台授权就不做代发布，不拿假入口占位。

## 五、下一批可复制的能力

托管台不是只能放两个动作。后续动作只要满足同一套契约，就能接进来：

- 有确定性输入与输出，金额可复核。
- 有已有真实执行链路，不靠模拟。
- 有幂等键，重复执行不产生副作用。
- 有明确的阻断条件与金额阈值。
- 执行结果能落台账，失败能说清原因。

候选方向：票据批量入账、平台账单对账、订阅续费提醒、发票查验结果入账。没有满足契约之前，只留入口，不写“已自动”。

## 六、判断标准

以后评审新功能，用这五条打分：

1. 用户是否少点了一次，而不是多学一个页面？
2. 手动出口是否还在？
3. 自动执行的边界是否写清，失败是否可见？
4. 是否复用了成熟 MCP/开放平台，而不是重造抓取器？
5. 是否留下可复核的证据，而不是只给一句“已完成”？

五条里缺两条以上，就不算差异化，只是加按钮。
