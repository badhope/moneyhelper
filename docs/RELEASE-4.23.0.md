## 一、这版改变了什么

### 1. 托管台：手动、助理、自动三档并存

每个动作都能单独设模式：

- **手动**：只出计划与证据，绝不执行。
- **助理**：先出计划，用户点一次确认才执行。
- **自动**：规则内直接执行；超过金额阈值、缺通道、有数据阻断时回落为待确认或阻断。

用户不需要离开系统去另一处配置。切换模式即保存，下一次评估就按新规则走。

当前只接两个真实动作：

- **税务核对包交接**：按当期生成包、选已就绪通道、按金额阈值判断是否要确认；执行复用 4.22 的真实 SMTP / 网关投递。
- **企业月结**：执行既有 `enterprise_month_end` 工作流，幂等键按租户 + 账期。

`一键托管` 会按「先月结、后税务交接」的顺序跑，避免税包在关账前生成。`只评估，不执行` 会给出计划但不触发任何外部动作。

### 2. 预设规则，而不是每次弹确认

- 税务动作可预设通道和自动执行上限；超过阈值自动停下等确认，`0` 表示不限。
- `auto` 不等于无脑执行：缺通道、数据阻断、金额超限都会回落。
- 每次评估、执行、阻断都落一条决策，保留 300 条/用户；页面能看到最近决策时间线。
- 同一底稿重复确认返回 `duplicate`，不重复发信、不重复 POST；页面明确写“此前已受理，本次按幂等键去重”。

### 3. 电商经营测算

- 输入 GMV、退款、订单数、平台佣金、支付费率、推广、货品成本、履约、其他成本与税项，输出净利、净利率、单均净利、客单价、退款率、当前 ROAS、盈亏平衡广告费/ROAS 与告警。
- 全部由确定性计算完成，模型不参与金额；参数改动自动重算，不需要点“计算”。
- 方案可保存、可删除，历史方案与当前测算并列对照；不写账、不改账。
- 默认参数结果：净利 ¥20,796.37、净利率 21.89%、退款率 5.00%、盈亏平衡 ROAS 2.66。

### 4. 不造轮子：开放平台与 MCP 入口

- 连接中心新增「电商经营」分类：抖店、淘宝、拼多多、有赞。授权后只读订单与账单，不代运营、不代下单。
- 插件市场新增 Playwright MCP（浏览器授权读取）：让 Agent 在用户授权下打开商家后台读取订单与账单，不代下单、不改价。
- 能通过成熟 MCP / 开放平台拿到的能力，不再自研抓取器；系统负责编排、鉴权与审计。

## 二、真实验收证据

- **手动模式运行 / 只评估**：金额 ¥30,000、通道「邮箱投递」、包 `TAX-202611-f9ccecd1`，只出计划未执行。
- **助理确认执行**：先得到待确认，再点确认得到已执行；统计从 0 已执行变为 1 已执行。
- **幂等去重**：同一包再次确认返回 `duplicate: true`，`external_deliveries` 未新增，页面显示“此前已受理，本次按幂等键去重”。
- **自动月结**：`month_end_close` 在自动模式真实执行，结果进入交接/自动化台账，决策记 `executed`。
- **电商方案**：保存“双十一大促测算”成功，历史方案显示净利 ¥20,796.37；删除后列表与提示同步清空。
- **目录**：连接中心「电商经营 4」四张卡可见；插件市场搜索 `Playwright` 命中 MCP 条目。

全量回归：

- 后端 `1975 passed`（261.90s）。
- 前端 `36 files / 247 tests passed`（71.74s）。
- `npx tsc --noEmit`、`npm run build` 通过。

## 三、没有假装做到的部分

- 托管台只延展已有的投递与月结，不新增税局直连、银行划款、法定合并或社区代发布。
- 税局直连仍需乐企/服务商；银行划款需持牌与授权；法定合并需审计口径；五个内容社区代发布需平台账号授权。
- `accepted` 只代表对端受理；`duplicate` 只代表同一底稿按幂等键去重。都不等于申报成功、付款成功或审计完成。
- 电商测算只做经营口径，不替代平台账单、法定报表和纳税申报。
- 内容社区暂停，本轮不新增假入口。
