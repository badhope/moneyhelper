## 这一版做了什么

托管台新增第五个真实动作 `invoice_post`。发票夹里已确认的费用票，不再只是文件状态；在规则内可一次生成已过账凭证，整批原子、幂等、可反冲。

规则边界：

- 只处理当前账期内 `kind=expense`、`status=confirmed`、且未入账的发票。
- 默认费用科目 `6602` 管理费用、进项税 `2203` 应交税费、应付 `2202` 应付账款；三科都能在卡片上改，但会校验科目类型与启用状态。
- 默认本批价税合计上限 `50000` 元，填 `0` 不限；单次最多 100 张，超过部分留在 `pending`。
- 采购应付已登记同一发票号的直接跳过；采购应付审批会写总账，不能再重复入账。
- 一张发票一张凭证：借费用（不含税）、借进项税、贷应付（价税合计）；税额为 0 不写进项税行。
- 执行走单事务：发票状态、日期、金额、税额在计划后任一变化，整批回滚。
- `invoice_postings` 以 `(user_id, invoice_id)` 幂等，重复执行不会生成第二张凭证。
- 每张发票写 `invoice_post` 溯源；凭证状态为 `posted`，可在总账反冲。

`run-all` 改为“发票入账 → 银行流水匹配 → 归因 → 月结 → 税务交接”。先把费用票落账，再做资金与分类收尾。

## 实际验收

演示重置后种入两张已确认费用票：

- 2026-11-05 潮州云仓商贸有限公司，办公耗材，价税合计 ¥113，税 ¥13，发票号 `42600001`
- 2026-11-08 顺丰速运有限公司，快递月结，¥220，税 0，发票号 `42600002`

真实 API 验收：

- 手动评估：`manual`，`count=2`，`amount=333.0`，不写凭证。
- 自动执行：`executed`，`posted=2`，写入 `GL-202611-0004` 与 `GL-202611-0005`。
- 凭证一：借 `6602` ¥100、借 `2203` ¥13、贷 `2202` ¥113；凭证二：借 `6602` ¥220、贷 `2202` ¥220。
- 重复评估：被幂等表挡住，返回 `blocked`。

浏览器验收：

- 只评估显示“只评估：为 2 张发票生成了入账计划，没有写凭证 / 本批价税合计 ¥333 / 待入账 2 张”。
- 切自动执行显示“已入账 2 张发票，生成 2 张已过账凭证，可在总账反冲”，状态徽章“已执行”。
- 发票夹两张都显示“已入账”；结算页合计仍是 ¥333、税额 ¥13。
- 暗色与 390×844 移动端均正常。

## 顺手修掉的两个真实问题

- 演示重置只清 `invoice_postings` 和 `invoices`，却留着上一轮的 `source='invoice'` 凭证；重置一次就多一批无法再从发票夹追溯的旧凭证。现在重置会连同这些凭证与凭证行一起清理。
- 无候选文案原先写“当期没有已确认的费用发票”，在发票已入账时会误导。现在改为“当期没有待入账的已确认费用发票（可能已入账，或采购应付已登记）”。
- 只评估与手动模式原先共用“手动模式”文案，自动模式下点“只评估”也会说成手动。现在按 `dry_run` 区分，发票/银行/归因分别显示“只评估：为 n 张/笔生成了计划”。

## 边界

- 不处理收入票、专票认证、税局发票查验。
- 不做发票—采购订单—入库单三方匹配；同号采购应付直接跳过。
- 不按商品行拆税率或科目；一张发票一张凭证。
- 不接税局直连、不代划款、不出法定审计意见；平台账单对账仍未实现。
