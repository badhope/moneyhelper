一、执行摘要

2024 年被称为大模型的“奇迹之年”，2025 年则被业界公认为 AI Agent 的“工程落地元年”，到 2026 年，Agent 已从“被动问答”转向“主动干活”，并开始接管企业级长周期任务与代码生产[9]。然而，行业在规模化落地中反复踩中同一个核心痛点——连续性：上一轮谈过什么、偏好和边界是否继承、任务推进到哪一步能否复盘。多轮对话超长、跨周任务、工具调用链越长，模型越容易“失忆”、指令遵循退化、推理成本指数上升[1]。

本报告系统梳理 2024–2026 年 Agent 的演进时间线与高频问题（按阶段归类），罗列业界关键论文与处理方案，汇总 OpenAI、Anthropic、Google、字节/DeepSeek、腾讯等大厂实践，并给出面向 Moneyhelper（对话优先个人理财智能体）的模型选型建议与分层落地路线图，重点补齐记忆、上下文压缩、长程任务与安全治理能力。

二、Agent 演进时间线（2024–2026）与阶段性问题

按时间轴梳理关键节点与每阶段暴露的问题，问题类型用标签标注（上下文记忆规划工具成本安全）。

  1. 2023 · 奠基（背景）ReAct（推理+行动）、Generative Agents（记忆/反思小镇模拟）、AutoGPT/BabyAGI、MemGPT（OS 分页式记忆）

    问题：单步推理可但长程无记忆、规划漂移。

  2. 2024H1 · 框架爆发Reflexion（语言自反思）、DSPy（编程化 prompt）、AutoGen/MetaGPT/AgentScope 多智能体、检索增强 RAG 普及

    问题：记忆会话隔离、工具 调用不可靠、规划 长任务漂移。

  3. 2024H2 · 推理拐点2024-09 o1 发布，OpenAI 推出 o1/o3 系列、Agent 开始具备“深思熟虑”

    问题：成本 长链思考 token 成本飙升、上下文 窗口仍是硬约束。

  4. 2024-11 · 协议标准开启Anthropic 发布 MCP（Model Context Protocol），统一“模型↔工具/数据”接口，被誉为“Agent 界的 USB-C”[3]

    问题：工具 接口碎片化。

  5. 2025 · Agent 元年 / 编码 Agent 爆发Claude Code、OpenAI Codex、Cursor 等编码 Agent 成熟；推理模型成标配；MCP 成为工具层事实标准（开源 1 万+ Server，SDK 月下载近 1 亿次）[3]；A2A/SCP 协议补充

    问题：记忆 长会话/跨任务遗忘（上下文流失）、成本 长上下文昂贵、安全 权限与审计。

  6. 2025-12 · 记忆转向“记忆资产”业界共识从“堆窗口”转向“独立 Memory 层 / 认知架构”，Agent 护城河从工具转向记忆资产[10]

    问题：记忆 记忆缺失成为交付卡点。

  7. 2026 · 长上下文标配与反思百万 Token 窗口成标配，但“长上下文即万能”迷思被打破；结构化记忆工程、分层存储、语义索引、主动遗忘成为主流；多 Agent 产品化（OpenAI DevDay 2026 Dots）；金融 Agent 密集落地（Anthropic 金融模板、Google Gemini 金融版、腾讯 WorkBuddy 金融版）[9]

    问题：上下文 注意力稀释/大海捞针失效、记忆 高保真召回、安全 金融级准入/审计/熔断。

结论：业界已从“无限堆 Token”转向“上下文工程 + 结构化记忆”，关键是让 Agent 记住、找准、忘得掉——这正是 Moneyhelper 需要补的核心能力。

五、最近热门方案 / 共识

  • 协议栈收敛：MCP（Agent↔工具）、A2A（Agent↔Agent）、上下文协议，分层协议栈趋于收敛[12]。
  • 从“复杂系统”到“合适的系统”：行业共识转向“构建最合适的系统”，而非堆最复杂。
  • 记忆资产化：Agent 护城河 = 记忆资产 + 认知架构（分层存储/语义索引/主动遗忘）。[10]
  • 编码 Agent 成熟：Claude Code / Codex / Cursor 已成为生产级；用模型选型看重“编码 + 工具调用 + 长上下文”。
  • Agent 安全合规：金融等高信任行业对 Agent 做准入、权限、审计与熔断的工业级标准。[9]

七、模型选型建议（兼顾长期能力与编码）

Moneyhelper 是金融数据分析 + 对话 Agent，需要可靠工具调用、数学/数据分析、长上下文、成本可控。综合业界对比，推荐优先级：

  • 主用 DeepSeek（推荐）：开源、数学/代码强、1M 上下文、推理成本可控，适配国产环境[6]。适合 Moneyhelper 做报表/分析/编码辅助。
  • 备选通义千问（qwen-plus）：国产稳定、长文本好，接口兼容。
  • 进阶 Claude / Gemini / GPT：若预算充足且偏重复杂编码，可用官方或中转 API；但成本较高。
落地：Moneyhelper 在设置页已支持 OpenAI 兼容端点，用户填 key + base + model 即可切换；输入区也加了“模型快捷切换”下拉。给用户配好 DeepSeek key 即点亮。

八、Moneyhelper 落地路线图

P0 · 地基（立刻做）

① 模型点亮（用户填 key）+ ② 长会话摘要压缩（compress 策略）：当会话历史超过阈值，用 LLM 把旧轮次折叠成摘要，保持上下文健康、控制成本、防失忆。

P1 · 记忆分层（近期）

③ 分层记忆：工作记忆（会话）＋长期记忆（已有关键词）→ 升级为向量语义检索（embedding）+ 主动遗忘；④ 反思：失败/低置信回答记入“经验库”，下次避免重复踩坑。

P2 · 扩展（中期）

⑤ 工具标准化（可选接入 MCP）；⑥ 多智能体/子任务分工（复杂分析拆解）；⑦ 审计日志 + 熔断，对齐金融级治理。
