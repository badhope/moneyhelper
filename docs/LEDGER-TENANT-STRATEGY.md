# 现有账本的 tenant_id 映射与双写评估（切片 7c）

> 状态：2026-11-12 评估稿。本文是工程决策记录，不是实施计划书。
> 范围：`D:\Moneyhelper`（`bd213b2` 起，工作区含切片 1-7b 的未提交改动）。

## 1. 结论先说

**现在不做双写，也不做账本迁移。**

理由不是"难"，而是**双写的前提还没成立**：

1. 双写要回答"同一笔流水在两个租户下谁是主"，而现在**个人租户 id == user_id**，
   切到企业租户后流水落在哪里，本质是"个人账本要不要并入企业账本"的产品问题，
   不是技术问题。技术上做得到，产品上没定。
2. 双写在"总账已经是事实来源"的前提下才有意义——那意味着单式流水要退化成
   总账的投影。现在的架构是**反过来的**：单式流水是主账本，总账是并行的新账套。
   两套账并存时双写会造出"两个真相"。
3. 影子模式（切片 7a）刚落地，权限点字典和真实实现的差异还没清零。
   在权限还没定型的时候做数据层迁移，等于同时改两件最容易出事的。

**建议的顺序：先收口权限 → 再定账套模型 → 最后才动数据层。**

## 2. 现状事实

### 2.1 两套账本现在并存，但归属口径不同

| 维度 | 单式流水（旧账本） | 复式总账（新账套） |
|---|---|---|
| 表 | `transactions` | `gl_accounts` / `gl_periods` / `gl_entries` / `gl_entry_lines` |
| 归属列 | `user_id`（= 登录用户 id） | `tenant_id`（= 租户 id） |
| 隔离方式 | SQL 里 `WHERE user_id=?` | SQL 里 `WHERE tenant_id=?` |
| 金额类型 | `REAL` | 整数分 |
| 业务闭环 | 记账 → 总览/财报/税负 | 报销 → 审核 → 凭证 → 付款 → 对账 |
| 备份 | 已在 JSON 备份内 | 已在 JSON 备份内（内部 id 重映射） |

其余旧表（`runs` / `sessions` / `budgets` / `members` / `paper_*` / `family_*` 等）
一律走 `user_id`；新企业域的 13 张表一律走 `tenant_id`。

### 2.2 租户映射链

```
JWT.sub = user_id
  └─ current_user_id()        ← 旧域（记账/持仓/会话/审计…）读这个
  └─ resolve_tenant_id(uid)   ← 企业域读这个
        ├─ 1. users.active_tenant_id（切片 7b 显式选择，且仍是有效成员）
        ├─ 2. 个人租户（id == user_id）
        └─ 3. 有效成员资格里角色最重的一个
```

**关键事实：个人租户 id == user_id。** 这意味着对老用户来说
"租户"目前只是"用户的另一个名字"，而不是一个独立的数据边界。

### 2.3 已经做过的隔离验证

- 企业域全部按 `tenant_id` 硬隔离，并有双租户负向测试（`test_org_shadow.py`、
  `test_gl_mvp.py`、`test_expenses_flow.py`、`test_banking_flow.py`）；
- 跨租户引用（部门/岗位/成员/科目/凭证/报销/付款/对账）都被应用层拒绝；
- 切片 7b 实测：切到企业租户后总账读的是企业那份，**个人流水原地不动**
  （`test_tenant_switch.py::test_switch_affects_enterprise_domain_only`）。

### 2.4 真实缺口（不修会出问题的那种）

1. **`user_id` 与 `tenant_id` 在旧域仍然是一一对应。**
   一个人加入企业后，他在企业里的总账和自己的流水是两套互不相干的数据。
   用户会问"为什么报销里的钱不在我的账上"——这是产品问题，不是隔离漏洞。
2. **没有"法人/账套"概念。** 路线图要求"一个企业可有多个法人与账套"，
   现在只有"租户"，`tenants.kind` 只有 `local/personal/enterprise`。
3. **旧域的 SQL 里有 14 处 `user_id=` 直写**，迁移时是主要工作量。
4. **备份恢复里 `transactions` 走 `user_id` 语义**，
   而总账表走 `tenant_id` 语义；一旦两套 id 语义混用，恢复映射会指向错误的行。

## 3. 三个候选方案

### 方案 A：保持现状 + 双写（不推荐）

**做法**：单式流水照旧按 `user_id` 写，同时按 `tenant_id` 再写一份到总账。

**为什么现在不能做**：

- 两套账的**权威性没定**。报销→凭证的闭环已经能在总账内自洽，
  再让单式流水自动生成总账凭证，就出现"总账里的凭证"和"流水的投影"两份真相；
- 单式流水是**聚合流水**（"咖啡 -28 元"），总账凭证是**科目过账**
  （"借 管理费用 28 / 贷 库存现金 28"）。两者不是一一对应：
  一笔流水可能跨科目，一笔凭证可能合并多笔流水。自动映射需要科目映射表 + 人工确认，
  这正是"发票验真 + 差异调整"那部分工作，现在还没有。
- 双写一旦上线，回滚困难：期间已经关了账、凭证已经过账，回退单式流水不会自动回退总账。

**前置条件**：科目映射表、凭证生成策略、差异处理流程、期间锁联动。

### 方案 B：迁移到 tenant_id（推荐方向，但不在本轮）

**做法**：给所有旧域表加 `tenant_id`，以 `tenant_id` 为唯一归属，
`user_id` 降级为"操作者"而不是"归属"。

**收益**：

- 租户成为真正的隔离边界，企业/个人/家庭共享可以共存于同一套模型；
- 旧域（记账/会话/审计）与新域（总账/报销）用同一把尺子；
- 角色/数据范围过滤不再需要"个人租户 == user_id"这个巧合。

**成本与风险**：

| 项 | 工作量 | 风险 |
|---|---|---|
| 旧表加 `tenant_id` + 回填 | 21 张表 | 低（加列 + 按 user_id 回填，个人租户 id == user_id 时是恒等映射） |
| 14 处 `user_id=` 直写改成 `tenant_id=` | 中 | 中（漏一处就是越权；靠现有负向测试兜底） |
| 复合主键表（`positions`/`subscriptions`/`debts`/`watchlist`/`goals`/`conversation_summary`） | 大 | **高**：主键是业务字段，要重建表 |
| 审计链 `user_id` 语义变更 | 中 | 中：哈希链含 `user_id`，历史行口径不能改，只能加列不改旧值 |
| 备份恢复映射 | 中 | 中：两套 id 语义混用最容易指错行 |
| 家庭共享（`is_shared`/`owner_id`）与租户的交叉 | 大 | **高**：目前是"成员共享"，不是"租户共享"，语义要重新定义 |

**必须先做的三件事**：

1. **法人/账套模型定稿**。`tenants.kind` 要能表达"一个企业有多个法人，
   每个法人有独立账套"，否则迁移完还是"租户 ≈ 用户"。
2. **复合主键表的去键方案**。`positions`/`subscriptions`/`debts`/`watchlist`/`goals`
   用业务字段做主键，多租户下必然冲突（两个租户不能同时有一个叫"茅台"的持仓）。
   要么加代理主键 + `(tenant_id, business_key)` 唯一索引，要么保持单式表不租户化。
3. **家庭共享语义定稿**。`is_shared` 表达的是"家人可见"，
   租户化之后要么变成"同租户可见"，要么保留为租户内的第二层共享。

### 方案 C：显式划界，不合并（当前采取）

**做法**：承认这是**两套账本**，UI 和文档上把边界说清楚：

- 个人理财域（记账/持仓/负债/目标/预算/模拟盘）→ 永远属于登录用户，与租户无关；
- 企业财务域（组织/总账/报销/付款/对账）→ 永远属于当前工作租户；
- 两域之间**不做自动同步**，只提供"从企业域导出到个人域"这种显式动作。

**为什么现在先做这个**：

- 切片 7b 已经把"企业域可切换、个人域不动"这件事做实并测过；
- 用户困惑的根因是"看不到边界说明"，不是"没有合并"——
  现在的 UI 只在组织设置页有一行小字提示，顶栏切租户后没有说明；
- 自动合并要做的事（科目映射、凭证生成、差异处理）都属于阶段 4，
  现在做会拖慢主线上真正要交付的东西。

**本轮要做的事**：把边界说明放到用户真正会看到的地方（顶栏切换器 tooltip、
企业域页面的统一提示），而不是只写在文档里。

## 4. 触发迁移的信号

出现下面任意一条，就应该启动方案 B（而不是继续双写）：

- 同一个用户需要**同时**在个人租户和企业租户里记账，并期望两边汇总；
- 需要**跨法人/账套**的合并报表；
- 家庭共享从"成员级"扩展到"组织级"（共享给部门而不是个人）；
- 审计要求"账本归属"和"操作者"分开记录（当前 `audit_logs.user_id` 两者混用）；
- 企业客户明确要求"数据必须按法人隔离，不能只是按用户隔离"。

## 6. 待决问题（需要产品口径，不是技术问题）

1. **"这个企业的账"和"我自己的账"是什么关系？** 是同一本账的不同视图，还是两本账？
2. **个人流水要不要能"升格"成企业账的一部分？** 如果要，是复制还是迁移？复制则双份真相，
   迁移则个人历史失去意义。
3. **一个企业能不能有多个法人？** 路线图说能，但当前 `tenants.kind` 表达不了。
4. **家庭共享与租户是什么关系？** 是租户内的一种共享，还是租户之上的家庭组？
