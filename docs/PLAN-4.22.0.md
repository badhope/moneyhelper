# 4.22.0 外部投递通道：真实 SMTP 与签名 HTTPS 网关

> 口径时间：2026-11-24。版本 4.22.0（上一版 4.21.1 外部协同界面可视化重构）。
> 目标不是把税局、银行、审计“看起来接通”，而是把资料包真实送出本机：能配邮箱就真发信，能配网关就真签名 POST；没有资质与密钥时明确停在未配置。

## 一、问题

4.21.1 解决的是“读得清”，但最后一步仍停在页面：资料包只能下载，再由人拿去邮箱发送或交到服务机构。用户要求继续推进“需要真实接入”的项目，接不通也不能留假按钮。

P2 的四类硬阻塞没有变化：

1. 税局直连申报/缴款需要乐企准入或服务商通道。
2. 银行/券商真实资金划转需要持牌通道与用户授权。
3. 集团法定合并需要审计口径、抵销与合并范围确认。
4. 五个内容社区代发布需要各平台账号、登录与发布授权。

这一轮不去伪造税局回执，也不假装资金已划出。能真实做的是“资料交接层”：

- 用用户自己的 SMTP 邮箱，把税务包、付款包、合并包真实发出。
- 用服务商提供的 HTTPS 入口，按约定签名把包体真实 POST 出去。
- 税局、银行、审计三类通道做成可配置适配器；签字密钥与地址到位才可用。
- 每一次测试、成功、失败都落库留痕；没配就说没配。

## 三、四类通道

| 通道 | ID | 可投递包 | 真实动作 | 资质前提 |
| --- | --- | --- | --- | --- |
| 邮箱投递 | `smtp` | 税务 / 付款 / 合并 | `smtplib` 真发信，JSON + SHA256 摘要 + 付款 CSV | 用户自己的邮箱与授权码 |
| 税费申报网关 | `tax_gateway` | 税务 | `httpx` 签名 POST | 乐企或服务商入口、签名密钥 |
| 付款指令网关 | `bank_gateway` | 付款 | `httpx` 签名 POST | 持牌支付/银行开放平台入口、签名密钥 |
| 审计交接网关 | `audit_gateway` | 合并 | `httpx` 签名 POST | 审计机构/交接平台入口、签名密钥 |

网关请求头：

- `X-MH-Timestamp`：ISO 时间戳。
- `X-MH-Signature`：`sha256=` + HMAC-SHA256(`timestamp.body`)。
- `Idempotency-Key`：由用户、通道、包类型、包 ID、来源摘要组合哈希，同包重复点击不重复外发。

只把 2xx 视为对端受理；3xx/4xx/5xx 记失败，保存状态码与响应片段。`accepted` 只代表对端收下请求，不代表税局申报成功、银行付款成功或审计意见出具。

## 四、安全边界

- 通道密钥只进 vault，列表不回显；`config_json` 只放主机、端口、地址、服务商等非敏感参数。
- 外部邮箱必须 STARTTLS 或 SSL；明文只允许本机联调，且需 `MH_ALLOW_LOCAL_CHANNELS=1`。
- 外部网关只允许 HTTPS；拒绝 URL 内嵌账号密码、内网与保留地址；本机 HTTP 联调同样需显式环境变量。
- 没有密钥、没有启用、地址缺失时 fail-closed；不会因为“点了投递”就默认成功。
- SMTP 用户名与授权码必须成对；网关签名密钥 16–128 字符。
- 投递幂等键唯一约束在数据库层；已受理的同一底稿再次点击返回 `duplicate`。
- 失败写 `HANDOFF_SEND_FAIL` 审计，不伪装成功；成功自动进入交接台账，避免“发出去了但台账没有”。

## 五、状态与展示

通道状态：

- 已就绪：启用、地址与密钥齐全，可测试、可投递。
- 未配置：没有任何配置。
- 参数不全：缺主机、端口、发件地址、收件人或地址/密钥。
- 未启用：配置已保存但开关关闭。

投递状态只允许 `pending / accepted / failed`。页面显示：

- 四张通道卡：状态、地址摘要、上次测试结果、缺项标签。
- 配置侧栏：SMTP 主机/端口/加密/用户名/授权码/发件人/收件人/主题前缀；网关地址/服务商/签名密钥/超时；密钥留空表示沿用旧密钥。
- 投递编排：选资料包、选已就绪通道、填备注；第一次点投递进入确认态，第二次确认才发出。
- 最近投递：资料包、通道、状态、回执号/错误、时间。
- 台账卡片：投递徽章显示已受理/失败/投递中与通道名。

## 六、关键修正

1. 通道目录漏 `channel_id` 导致 `readiness()` 识别成 `unknown`，四张卡都显示“未知通道”；补 `channel_id` 后恢复。
2. 税务包的 `filing_channel`、付款包的 `execution_channel`、合并包的 `audit_basis` 本身就是“无外部通道”的阻断项，不能反过来阻断投递；现在只拦真正的数据阻断项与 `missing` 包。
3. 无密码的本机 SMTP 已就绪但前端按 `configured` 禁用测试按钮；测试按钮改为按 `ready` 判断，避免“通道可用却点不了测试”。
4. 投递摘要原先在发送后才补附件数，但未回写数据库，导致审计摘要显示 `attachments: 0`；现在在创建投递前按包类型计算并落库，SMTP 税务包固定 2 个附件。
