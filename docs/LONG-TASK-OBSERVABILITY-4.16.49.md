# 4.16.49 长任务：运行中可见、过期不误伤、投研跑满

## 这轮补的是什么

4.16.48 把“阶段契约、过期重算、检查点回滚、只读工具”做进了代码，但还有三个现实缺口：

- 工具阶段实测 170 秒，界面只有一个“执行中”，用户不知道模型是卡死还是在查数；
- 只要重跑上游就无条件把下游标过期，哪怕产物一个字节没变，零差异重跑也会制造假过期；
- 投研模板只真实跑了首段，市场段、结论段、执行清单仍停在 `pending`，“4/4 可跑”没有证据。

这轮不新增板块，只把这三件事收口。

## 运行中进度

执行器在每次真实工具完成后写 `stage.progress`：

```json
{
  "phase": "tool",
  "steps": 2,
  "last_tool": "get_ledger_view",
  "label": "已调用 get_ledger_view（第 2 步）",
  "updated_at": "2026-11-24T01:45:06"
}
```

阶段开始时先写“工具核实中（第 1 次）”或“模型生成中（第 1 次）”。前端在轮询任务详情时，阶段行直接显示“已调用 get_ledger_view · 第 2 步”，不是等结束后才补一个工具数量。

阶段成功、失败或取消时 `progress` 清空；检查点不保存进度，契约也不校验进度。它只回答“现在在干什么”，不回答“做完了没有”。

## 差异化过期

阶段新增 `artifact_sha256`：

- 首次成功时写入正文 SHA-256；
- 重跑前读取旧摘要；重跑成功后比较新摘要；
- 只有旧阶段状态是 `done` 且摘要确实变化，才把下游标 `stale`；
- 摘要相同则只更新耗时、检查点与工具记录，不改变下游有效性，任务保持 `done`；
- 回滚也按同一规则比较当前正文与恢复正文，相同就不误标。

这是字节级比较，不是语义比较。它不能判断“换了同义词但意思一样”，但能保证“模型原样重写一遍”不会被当成上游变更。

## 边界

- 进度是工具完成后的心跳，不是 token 级流式输出。模型在两次工具之间思考时，仍只能显示上一条工具或“模型生成中”。
- 摘要按字节比较；标点、空格变化都会判为变化，宁可多标一次过期，也不漏标真实改动。
- 检查点仍是单阶段最近 6 份，没有任务级整体快照、分支版本或跨设备同步。
- 工具阶段只读，写账、改持仓、下单仍不进入无人值守长任务，没有 HITL 审批循环。
- 长任务仍是阶段执行器，不是可自主规划、可自我验证的通用 agent。
