# 4.16.48 长任务：契约、失效、回滚与只读工具

## 解决的问题

4.16.47 解决了单阶段重跑，但长任务仍然只能证明“模型返回了文字并写进了文件”：

- 没有交付标准：50 字也能标完成，缺小节也能叫“报告”；
- 上游改了、下游还挂着旧结论，任务状态却仍显示 `done`；
- 产物写坏了只能重跑，没有可回退的历史版本；
- 所谓“工具阶段”只是提示词里写一句“可以查数据”，模型实际没工具，数字仍可能凭空来。

这四件事不解决，长任务就只是把聊天拆成几段，不能称为可交付的执行系统。

## 这次落地的能力

### 1. 阶段契约与产物校验

新文件 `backend/app/longtask_contract.py`，契约字段固定为：

- `min_chars`：正文最低字数，上限受 `max_chars` 约束；
- `max_chars`：正文上限，默认 12000，最高 12000；
- `required_sections`：必须出现的小节名，最多 8 个；
- `forbid_placeholders`：禁止 `TODO`、`待补充`、`此处省略` 等占位内容；
- `use_tools`：该阶段是否走只读工具循环；
- `route`：`ledger` / `market`，决定工具面。

执行器在落盘前调用 `validate_artifact` 做确定性检查：空产物、字数不足、缺必需小节、含占位符都会返回具体违反项。首次不合格会用同一阶段重写一次，第二次提示词直接带上一次违反项；两次都不合格则该阶段 `failed`，不写正式产物，错误写成“产物未通过契约：字数不足：…”。

旧任务兼容：没有 `contract` 的任务按 `min_chars=0` 处理，只保留“非空”底线，不会被新模板标准追溯判死。

模板全部升级为 `(name, instruction, contract)` 三元组，新增 `research`（投研报告）模板，四个阶段分别定义最低字数、必需小节与是否用工具。前端详情显示“交付契约：≥N 字 · 必需小节 · 只读工具”，失败阶段展开显示具体违反项。

### 2. 依赖失效与下游重算

阶段新增 `stale / stale_reason / stale_at`。任一阶段成功重跑或回滚后，它之后已完成的阶段全部标为过期：

- 旧产物保留，供对比与回滚，不删除；
- 任务状态回到 `pending`，不再假装 `done`；
- 列表显示“N 个过期”，详情顶部出现橙色横幅“有 N 个下游阶段基于旧产物，结论可能已经过期”。

两种重算入口：

- `cascade`：从指定阶段起重算该段及全部后续，body 为 `{"stage_index": 0, "cascade": true}`；
- `stale_only`：按阶段顺序只重算所有过期阶段，后一段吃到前一段的新产物，body 为 `{"stale_only": true}`。

顺序语义同时收紧：阶段是顺序依赖，任一阶段失败即停，下游保持 `pending`，不再拿残缺上下文继续产出“完成品”。这推翻了 4.16.47 的“失败不中断后续”，对应测试已改写。

### 3. 检查点与回滚

新文件 `backend/app/longtask_checkpoints.py`。每次成功阶段运行写两份文件：

- `<id>.json`：提示词、契约、字数、耗时、attempt、`tools_used`、工具步骤摘要、来源；
- `<id>.md`：当时的完整产物。

每阶段保留最近 6 份。检查点 ID 带微秒，列表按 ID 倒序，避免同一秒内多次重跑导致顺序不稳、回滚选错版本。

回滚 `rollback_task`：

- 运行中的任务拒绝回滚；
- 回滚前把当前版本自动写成 `pre-rollback` 备份；
- 恢复目标检查点的原文与元数据；
- 下游标过期，任务状态按真实阶段状态收口。

API：

- `GET /api/longtasks/{id}/stages/{index}/checkpoints`
- `POST /api/longtasks/{id}/rollback`，body `{"stage_index": 1, "checkpoint_id": "..."}`

前端展开阶段显示“历史版本”，每条含时间、字数、工具与来源；回滚前弹 `window.confirm`。

### 4. 阶段级只读工具自治

`_run_tool_stage` 复用主 Agent 的 `agent.run_agent` function calling 内核，工具面按 `route` 走 `build_toolset`，只注入 READ 档工具。`TOOL_STAGE_SYSTEM` 明确：只能调只读工具、数字要有出处、查不到就写查不到、只交付当前阶段成果。

阶段记录真实 `tools_used` 与 `tool_steps`（工具名、参数、摘要、状态、耗时），UI 与检查点都能看到，不是写死文案。写操作不进入无人值守长任务，本轮边界到此为止。

## 真实验证

### 单阶段工具循环

任务 `2abf09ea156b`，标题“4.16.48 契约与工具验证”，`research` 模板：

- 首阶段“数据与口径”，契约 `≥250 字 / 必需小节：数据、口径 / 只读工具：ledger`；
- 真实模型走了 3 轮工具循环，调用 `get_trend`、`get_ledger_view`、`get_financial_identity`；
- 耗时约 2 分 50 秒，产出 1044 字，契约校验通过；
- 产物如实写出“净资产 0、流水 0、趋势为空、预期月收入 24800 非实际流水”，没有编造；
- 检查点 `20261123T184546482270-fa1a`，`tools_used` 与步骤均已落盘；
- 任务 1/4，其余阶段 `pending`。

### 过期与重算

任务 `0886e1cabd0a`，两阶段各 ≥80 字：

1. 首次全跑：阶段 0 耗时 13.7 秒 / 275 字，阶段 1 耗时 11.7 秒 / 371 字，任务 `done`；
2. 重跑阶段 0：阶段 1 立即标 `stale`，原因“上游「现状」已重算，本段基于旧产物，需重算确认”，任务回到 `pending`，`stale_count=1`；
3. 点“重算过期阶段”：只重算阶段 1，39.2 秒 / 589 字，任务回到 `done`，过期标记清除。

### 检查点与回滚

同一任务阶段 1 已有两份检查点（589 字与 371 字）。回滚到 371 字版本：

- 回滚前自动生成 `pre-rollback` 备份，界面出现第三份 589 字历史；
- 正文恢复为 371 字版本，阶段状态 `done`；
- toast 返回“已回滚，下游阶段已标记过期”。

## 边界

- 契约只看可观测文本：字数、小节名、占位符。它不能判断事实真假、引用是否真实、结论是否成立，也不替代人工审稿。
- 过期按阶段顺序粗粒度标记：上游任何成功重跑都会把后面所有已完成阶段标过期，不比较新旧产物差异。零差异重跑也会触发下游过期，这是保守选择。
- 检查点存本地文件，每阶段只留 6 份；没有跨设备同步、没有任务级整体快照、没有分支式多版本并行。
- 回滚是覆盖当前产物，不是回到某个历史任务状态；回滚本身也会标下游过期，仍需人工决定是否重算。
- 工具阶段只读：不执行写账、不改持仓、不下单；没有为写操作设计 HITL 审批循环。
- 工具阶段实测单段约 170 秒，长任务整体耗时与模型轮次线性相关。这是真实工具调用的代价，不是可以靠 UI 隐藏的延迟。
- 长任务仍是有边界的阶段执行器，不是可自主规划、可自我验证的通用 agent。
