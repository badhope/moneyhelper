## 一、交接台账

`GET /api/external/handoffs?limit=20`，读权限沿用 `gl:read`。

- 合并 `HANDOFF` 与 `HANDOFF_ACK` 两类审计事件，按 `packet_id` 归并。
- 每条显示类型、期间、包标识、来源摘要、包状态、备注、留档时间/人和线下确认时间/备注。
- 状态只有 `archived`（已留档）与 `handed_over`（已线下交接）。
- 响应含 `total`、`archived_count`、`handed_count` 与边界说明。
- 默认 20 条，最大 100；读取固定按当前用户审计记录，不跨用户拼接。

## 二、留档

`POST /api/external/handoffs`，写权限沿用 `gl:write`。

```json
{"kind": "tax|payment|consolidation", "period": "YYYY-MM", "group_id": "", "note": ""}
```

- 调用现有 `tax_packet` / `payment_packet` / `consolidation_packet` 生成包，不另算一套数字。
- 计算并保存 `packet_id`、`source_hash`、`packet_status`，追加 `HANDOFF` 审计事件。
- 同 `packet_id` 已留档时直接返回旧记录，`created=false`，不重复插入。
- `kind` 非法、期间非法、合并包缺 `group_id` 返回 400；集团不存在/无权沿用 404。
- 备注限 120 字；`detail` 存 JSON，受审计函数 500 字符截断。

## 三、线下交接确认

`POST /api/external/handoffs/ack`，写权限沿用 `gl:write`。

```json
{"packet_id": "TAX-202611-xxxxxxxx", "note": ""}
```

- 只允许已留档的包确认；未找到返回 404。
- 追加 `HANDOFF_ACK`，状态变为 `handed_over`，记录确认时间与备注。
- 重复确认返回旧记录，`updated=false`，不重复写审计。
- 不校验对方是否收到、不上传第三方、不改变申报/付款/审计状态。

## 四、来源摘要

- 4.20.0 只有合并包带 `source_hash`；4.21.0 给税务包与付款包补 32 位稳定摘要。
- 摘要覆盖整份包除 `generated_at` 与 `source_hash` 外的全部字段。
- 留档优先使用包自带摘要；台账与当前页面同 `packet_id` 包比对，一致显示绿色徽标，不一致显示红色。
- 包内容随账务变化时 `packet_id` 会变化；旧留档保留原摘要，不会被新包静默覆盖。
