# 4.16.47 长任务单阶段控制与状态语义

## 解决的问题

4.16.46 已经能后台执行与真取消，但继续执行只有“整批续跑”：
- 一个 6 阶段任务失败第 1 段，点执行会把后面所有待执行阶段也一起跑，成本和等待不可控；
- 单阶段产物不理想时，无法只重算这一段；
- `max_stages` 或单阶段执行结束后，任务仍可能停留在 `running`，前端误以为后台还在跑并持续轮询；
- 进程重启后磁盘残留 `running`，界面会一直显示“执行中”。

## 这次落地的能力

### 单阶段重跑

- `POST /api/longtasks/{id}/run` 新增 `stage_index`；与 `max_stages` 二选一。
- 只执行目标阶段，已完成的其他阶段与产物保持不动；目标阶段之前的产物仍作为上下文。
- 失败、已取消、已跳过的阶段在详情页出现“重跑此阶段”；不会误触正常待执行阶段。
- 目标阶段运行中时拒绝重复启动，避免同一阶段并发写同一个产物文件。

### 状态语义修正

- 任务状态只表示真实状态机：有后台协程才是 `running`；执行器退出但仍有待执行阶段则回到 `pending`。
- API 返回 `active`，区分“状态机 running”与“确实有协程在跑”。
- 进程重启残留的 `running` 会在读取时归一为 `pending`，并在下次执行时把残留 running 阶段重置为待重跑。
- 前端只在 `running && active` 时轮询；本次部分执行结束后停止轮询并提示“仍有待执行阶段”。

## 验证

- 后端全量 `1916 passed`；`test_longtask.py + test_capability_depth.py` 17 项通过；新增单阶段重跑用例与磁盘 running 恢复用例。
- 真实浏览器：已取消任务的“世界观与人物”阶段点“重跑此阶段”，只跑该段 25.6 秒、生成 658 字，任务从停驻状态变为 `1/6 待执行`，其余 5 段未动。截图 `152`。
- 任务列表中原残留 `running` 的“阶段遥测验证”已正确显示“待执行”，不再无限轮询。

## 边界

- 单阶段重跑可能让后续已完成的阶段基于旧上下文；当前策略是保留后续产物、不自动级联重算，避免一次点击产生不可控成本。
- 仍不支持任意时点回滚；只支持单阶段重算。
- 长任务仍是 LLM 分段生成，不是带工具的自治 agent。
