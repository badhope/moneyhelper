# 4.16.46 全量功能真伪审计与 Agent Harness 对标复核

> 审计目标不是找 TODO，而是逐条确认“界面 ↔ 设置键 ↔ API ↔ 后端消费 ↔ 持久化/副作用”是否闭合。
> 结论先说：本轮找到并修复 5 个“看起来存在、实际不生效或结果不对”的真问题；原有 Harness P0/P2/P3 基本可用，P1 只做到工具轨迹级回放，没有把部分完成包装成全部完成。

## 一、审计方法

1. 扫种子设置键，逐个在全仓找消费方，排除 schema / 设置路由 / 恢复白名单等纯登记文件；无消费方即 `DEAD`。
2. 从 UI 控件追到 API，再追后端实际调用与落库字段；不按“文件里有函数”判定完成。
3. 对 Agent 工具循环、长任务执行器、审批、评测、事件回放、模型路由做路径级核验。
4. 真实浏览器验收，不以单元测试替代可见状态与交互结果。

## 二、发现的真问题与整改

### 1. 两个设置键完全没有消费方

- `auto_refresh`、`auto_refresh_seconds` 只存在于 schema 与设置表单，没有任何定时器。
- 整改：Dashboard 从 bootstrap 读取开关与间隔；间隔 30–86400 秒；`document.hidden` 时暂停，卸载清理定时器。偏好页增加真实开关与秒数输入。
- 验证：浏览器实测开启后出现 60 秒输入；`GET /api/settings` 返回 `on / 60`。

### 2. `default_tab` 保存了但 App 从未读取

- 旧选项还保留了已经不存在的 `features` 页面；后端合法值也与前端视图不一致，`tax/debts/gl/expenses/procurement/longtask/bank` 等真实页面无法设为默认首页。
- 整改：App 初值优先读 `sessionStorage["mh.defaultTab"]`，bootstrap 到达后只应用一次；非法旧值静默忽略；后端 `DEFAULT_TABS` 与前端 `DATA_KINDS` 全量对齐；对话式“把默认首页改成税务/总账/长任务”等口语映射补齐。
- 补修：默认首页下拉动态翻译 `nav.overview`、`nav.health` 缺键，界面直接显示 `nav.overview` / `nav.health`；已在中英文字典补齐。
- 验证：设为总览后重载，应用落在总览；截图 `144`。

### 3. Agent 上下文压缩几乎永远不会触发，且可能切出非法消息

- 原实现只在进入工具循环前压一次，当时消息只有 system + user；真正膨胀的是 assistant(tool_calls) 与 tool 结果链。
- 按消息条数截断可能从 tool 消息中间切开，形成没有前置 `tool_calls` 的孤立 tool 消息，OpenAI 兼容端点会 400。
- 整改：统一复用 `context.compact_messages`；`_safe_keep_start` 在切点落在 tool 时回溯到对应 assistant(tool_calls)；当前轮超长工具结果只截头部并标注；每轮工具结果回填后按 token 预算压缩；新增设置 `agent_context_tokens`（默认 12000，范围 2000–128000）。
- 验证：回归断言压缩后不存在孤立 tool 消息；截图 `146`。

### 4. 动态工具面此前只有白名单，没有按路由真实收窄

- `_ROUTE_TOOLS` 已定义，但 `build_toolset` 没有使用。
- 整改：`build_toolset(..., route=...)` 在 `tools_list is None` 时按路由过滤；`market` 不含 `get_ledger_view`，`ledger` 不含 `get_kline`，`both`/未知路由保留全量；`run_agent` 与 `finalize` 传递真实 route。
- 验证：回归断言两套工具面互斥且保留核心工具。

### 5. 长任务的“运行/取消”语义不真实

- 运行接口是同步 HTTP，任务可能跑几十分钟；取消只写 JSON，后台协程继续生成，跑完还可能覆盖成 `done`；后台启动若模型未配置，接口成功但任务永远 pending。
- 整改：进程内 `_JOBS` 登记；`start_task` 后台启动并前置检查模型可用；`cancel_task` 先写 `cancelled` 再 `job.cancel()`；`CancelledError` 落 `cancelled` 不被覆盖；异常由 done callback 落 `failed + error`。
- 浏览器追加发现：任务顶层显示“已取消”，阶段仍显示“执行中”，用户无法判断后台是否真停。
- 补修：取消时同步把 running 阶段落成 `cancelled` 并写中断原因；取消后的任务允许继续执行；前端每 3 秒轮询，终态停止。
- 验证：真实浏览器启动后台任务、取消后列表与阶段均显示已取消，阶段原因“用户取消，当前阶段已中断”；截图 `147`、`148`。

### 6. 历史工具轨迹实际从未落库

- `runs.steps_json` 已加列，`save_run` 已支持 `steps`，但最终回包只暴露 `agent_steps`，`qa.py` 读的是 `steps`，所以新记录永远保存 `[]`。
- 整改：最终回包与 `agent_enterprise` 同时暴露 `steps` 与 `agent_steps`；`qa.py` 继续读 `steps`；工具步骤补充 `status` 与 `duration_ms`；前端历史回放保留真实状态与耗时。
- 浏览器发现：流式期间同一次工具调用同时收到 `tool` 与 `agent_step`，1 个工具显示成“调用了 2 个工具”。
- 整改：`agent_step` 对紧邻且内容一致的工具去重；工具展开行补充参数 JSON（截断 160 字符），让回放不只看到结果摘要。
- 验证：新回答刷新后仍显示“调用了 1 个工具”，展开可见工具名、结果摘要、参数与耗时；截图 `149`。

### 7. “财务数字身份证”被路由到企业域，工具面里没有该工具

- 提示“请调用 get_financial_identity”时，模型兜底把问题判成 `enterprise`，实际调用 `get_gl_summary`，并回答“没有名为 get_financial_identity 的工具”。
- 整改：`route_question` 对“财务数字身份证 / 财务身份证 / 财务画像 / financial identity / get_financial_identity”先钉死 `ledger`，避免“财务”二字被模型误判成企业总账。
- 验证：真实浏览器重问后路由为 `ledger`，模型实际调用 `get_financial_identity`，返回身份证号与净资产；数据库 `runs.steps_json` 记录该工具。

## 四、扩展与优化：不是修好就算完

修复只解决“能不能用”，扩展要解决“用起来是否可判断、可复盘、可继续”。

### 1. 长任务：从只有状态升级为可观测执行

- 每个阶段记录 `attempts`（实际尝试次数）与 `duration_ms`（阶段耗时），成功、失败、取消三条路径都会落盘。
- 尝试次数在模型调用前落盘，取消读取磁盘快照时不会出现“重试 0 次”的假数据。
- 详情页显示 `已完成/总阶段 · 失败数 · 重试次数`，单阶段显示耗时；重试过的阶段标“尝试 N 次”。
- 这解决的是：用户原来只能看到“失败”，不知道是一次失败还是重试后仍失败，也不知道慢在哪一段。
- 浏览器实测：真实模型完成第一阶段，界面显示 `1/2 阶段完成`、`19.9s`、`108 字`；截图 `150`。

### 2. 聊天工具轨迹：从“调了几个”升级为“调得怎么样”

- 聚合行增加总耗时与失败数，不展开也能判断这次任务是否变慢、是否有工具报错。
- 展开后仍保留单步状态、耗时、参数与结果摘要，形成“总览 → 单步”的两级可观测。
- 浏览器实测：真实调用 `get_financial_identity` 后显示“调用了 1 个工具 · 810ms”，回答给出 `584D`；截图 `151`。

### 3. 各类任务分别优化了什么

| 任务类型 | 优化点 | 扩展点 |
|---|---|---|
| 普通问答 | 每轮工具结果后按 token 预算压缩，避免上下文超窗 | 工具轨迹总耗时/失败数，不展开也能判断 |
| 市场/账本问答 | 按路由只给相关工具，减少小模型误选 | 路由短语钉死，避免“财务”被误判企业域 |
| 长文/深研 | 轻量与深度模型按难度分流，同一端点内换模型 | 长任务阶段耗时、尝试次数、进度汇总 |
| 设置类任务 | 设置键必须有真实消费方，启动即生效 | 自动刷新支持隐藏暂停与间隔边界，默认首页覆盖全部真实视图 |
| 写操作任务 | 大额走 HITL，一次性 token，失败落 failed | Agent 工具面保持只读，模型不能绕过审批直接写 |
| 长任务 | 后台执行、真取消、失败隔离、验收标准入提示词 | 每阶段可观测；失败阶段可再次执行续跑 |
| 数据回放 | 工具步骤随 run 落库 | 状态、耗时、参数一起回放，旧记录安全退化 |
