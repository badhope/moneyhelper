## 这一版做了什么

托管台新增第三个真实动作 `attribution_confirm`。它只处理当前账期的收支归因候选，默认手动模式；切到自动后，只在预设规则内执行。

规则边界：

- 只自动确认规则命中（内置规则或自定义规则），不自动确认“历史同类”。历史只能当参考，不能替用户判断同一商户这笔钱到底算什么。
- 默认最低置信度 `0.7`，默认本批合计上限 `10000` 元；填 `0` 表示金额不限。
- 单次最多 100 条；超过部分在计划里显示，留给下一轮，不静默丢掉。
- 合计金额超过上限时，自动模式也停在“等你确认”。
- 只改流水分类，不改金额、日期与余额；执行走单事务批量确认，分类若在计划后被改动会整批拒绝。
- 每条确认写快照与溯源证据，可在归因页逐笔回滚。

`run-all` 改为“归因 → 月结 → 税务交接”。先把分类确认掉，后面的月结与税务包才不会带着“其他/未分类”的噪音。

## 实际验收

演示账本造了两笔“云仓耗材”流水：

- 2026-11-18 打包胶带 ¥68，分类“其他”
- 2026-11-20 标签纸 ¥80，分类“其他”

创建自定义规则“云仓耗材 → 办公采购（支出）”，托管台手动评估得到 2 笔候选、合计 ¥148；切自动执行后显示“已确认 2 笔流水分类”，分类写回为“办公采购”，溯源链有记录。

暗色与 390×844 移动端均已验收；三张动作卡在桌面端为三列，移动端单列。

## 边界

- 这轮没有新增税局直连、银行划款、法定合并或社区代发布。
- 发票批量入账、平台账单对账、订阅续费提醒仍是后续项；没有拿“目录入口”或“上传预览”冒充已完成。
- 托管台只延展现有的归因、月结与投递能力，不代表税局已申报、银行已划款或审计已出具意见。
