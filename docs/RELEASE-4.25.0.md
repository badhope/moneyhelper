## 这一版做了什么

托管台新增第四个真实动作 `bank_match`。它只处理当前账期内“未匹配的银行支出”，默认手动模式；切到自动后，只在预设规则内执行。

规则边界：

- 只配同租户、同银行账户、同金额、日期相近的付款；付款必须已付款，流水必须是支出且未匹配。
- 默认日期窗口 `3` 天，可配 `0–30` 天；默认本批合计上限 `50000` 元，填 `0` 表示不限。两项都能在银行卡上直接改。
- 单次最多 100 条；超过部分在计划里显示，留给下一轮。
- 同一流水命中多笔付款、或同一付款命中多条流水时，整组判为歧义，跳过。宁可留给人工，也不猜。
- 合计金额超过上限时，自动模式也停在“等你确认”。
- 执行走单事务批量匹配，任何一笔失效整批回滚；每条写溯源，可在银行页撤销。
- 只改流水与付款的匹配关系，不动金额、余额、日期与凭证。

`run-all` 改为“银行流水匹配 → 归因 → 月结 → 税务交接”。先把资金侧配对，再做分类与月结。

## 实际验收

演示账本重建后种了两组银行数据：

- 2026-11-18 云仓耗材 ¥148，付款 `PAY-DEMO-4250-1`
- 2026-11-20 顺丰月结 ¥220，付款 `PAY-DEMO-4250-2`

托管台银行卡手动评估得到 2 笔候选、合计 ¥368、窗口 3 天，结果明确“只生成了计划，流水没有配对”；切自动执行后显示“已配对 2 笔流水与付款”，两条流水状态为 `matched`，溯源链新增两条 `bank_match`，记录付款号、金额、流水日期与账期。

桌面端四张动作卡为 2×2，避免 1040px 内容区把卡片压到 240px；暗色与 390×844 移动端均已验收。

## 边界

- 这轮没有新增税局直连、银行划款、法定合并或社区代发布；也不接银行直连，流水来自用户导入。
- 发票批量入账、平台账单对账仍是后续项；没有拿“目录入口”或“上传预览”冒充已完成。
- 托管台只延展现有的流水匹配、归因、月结与投递能力，不代表税局已申报、银行已划款或审计已出具意见。
