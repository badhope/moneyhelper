## 二、能力扩展路线
### 纵向（做深——护城河）
1. **导入增强**：银行账单 PDF → 自动分类准确率 eval 基线（目标 >95% 才算及格）
2. **主动财务管家**：订阅涨价检测、账单异常提醒、月度结余漂移告警（scheduler 已有，加规则）
3. **年度财务报告**：确定性数据 + LLM 叙述 + PDF 导出
4. **beancount 导出**：接入纯文本记账生态，吸引开发者群体
5. **多币种**：跨境记账（汇率源接 MCP 外部服务器）

### 横向（做广——触达）
1. **技能包市场**：MCP Registry 分发 + Agent Skills 规范对齐（生态引擎）
2. **家庭多账本聚合**：多成员已有 → 聚合视图/权限分级
3. **多端壳**：AG-UI 对齐后，Tauri 桌面端 / 微信小程序 / TUI 三选一先行（建议 Tauri，复用 React 前端）
4. **外部 agent 接入文档**："把 Moneyhelper 接进 Claude Code / Cursor / Cline"三篇教程（获客）

## 三、模块化/标准化/可运维改造（引用前沿实践）
### 拆分（P3 架构债 → 模块化）
- db.py(2927) 按域拆：users / transactions / positions / settings / sessions_history 五模块，`db/__init__.py` 门面保持兼容
- main.py(1940) 拆：settings 路由、qa SSE 路由入 routes/；lifespan/中间件入 app_factory.py
- 参考：Codex Harness 状态机 + LangGraph 官方示例项目结构

### 标准化
- 工具层：pydantic schema 化（hermes/Agents SDK 风格）→ 全量 MCP 暴露
- 事件契约：SSE → AG-UI 映射层（大厂已背书，前端组件可换装）
- HITL：MCP Elicitation 标准形态；长任务：MCP Tasks
- 数据库迁移：alembic 全覆盖（现 _migrate_add_columns 手写列补丁是过渡态）

### 可运维性（引入策略）
- **观测三层 span**：LLM（litellm 自带）/ 工具（provenance 已有数据，接 OTel）/ DB（aiosqlite 慢查询日志）
- **限流**：换 cachetools.TTLCache（requirements 已引入却没用在限流上）+ 修首请求计数 bug
- **健康检查**：/healthz 细化（db/llm/mem/scheduler 四探针）
- **测试封闭**：行情 mock 化 + CI 分层（单测/E2E）
- **错误预算意识**：SSE 断线重连协议（Last-Event-ID）——前端断线丢事件的体验问题
- **配置规范**：.env.example 全量键位 + 启动时 schema 校验（pydantic-settings）
