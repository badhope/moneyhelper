## 已实锤问题（后端）

### P1（功能真 bug）
1. **llm.py L491 `litellm_chat()`**：`api_key=cfg.get("api_key")` — 配置字典的键是 `"key"`（见 L84/103），API key 永远传 None。调用方（mem0 抽取/评估路径）在纯 DB 配置时必然鉴权失败或匿名。同文件 L388 `_CompatCompletions` 用的是 `cfg.get("key")`，只有 litellm_chat 写错。
2. **service.py `_try_nl_add()` L161-163**：多段记账注释声称「全部可解析才入账（原子）」，实际逐条 `await db.add_transaction(...)`，无事务包裹。第 N 条 insert 失败时前 N-1 条已入库，非原子。
3. **main.py batch_undo**：body 校验失败返回 `status_code=402`（Payment Required），应为 400。

### P2（设计/可靠性）
4. **main.py `_rate_limit_check`**：新 IP 首次请求 bucket 为空 → 直接放行且不计数，每 IP 每分钟实际配额 +1；`_rate_buckets` 全局 dict 无清理上限（靠 pop 单个过期键，极端下内存增长）。
5. **agent_graph.py**：`_savers`/`_exec_graphs` 用 `id(loop)` 做 key 缓存图对象 — 事件循环 GC 后 id 可被复用，理论脏缓存；单 loop 场景低危。
6. **main.py**：`/api/metrics` 在 `_SKIP_AUTH_PATHS` 白名单里 — Prometheus 指标无鉴权可拉（内网泄露面）。
7. **路由英文支持弱**：route_question 全部中文关键词表，英文提问（"how much did I spend"）走 general 或依赖 LLM 兜底分类。
8. **llm.py stream_narrate**：`retry_policy={"retry_timeout":30}` 不是 litellm 有效参数形态（RetryPolicy 对象字段），疑似被静默忽略；docstring 声称的 DeepSeek reasoning_content 解析实际未实现。

### P3（架构债）
9. **main.py 1940 行巨石**：routes/ 目录已建但只拆了 10 个子路由，设置/问答/SSE/静态托管仍堆在 main.py，与 db.py（2927 行）同为维护热点。
10. **service.py `ensure_session_summary`**：`fetch_all` 全量拉会话 runs 判断阈值，长会话下每轮全表扫。
