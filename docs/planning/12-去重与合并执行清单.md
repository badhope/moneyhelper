# 去重与合并执行清单（真实代码扫描版）

> 2026-11-19 · 基于 `gitcode.com/badhope/moneyhelper` 实际代码扫描（v4.16.0，commit `cfd33e6`）
> 本文只记录**在代码里验证过**的重复项与处置结果，不写推测。所有行号取自改造前。

## 〇、真实基线（扫描结果）

| 维度 | 实测值 |
|------|--------|
| 后端 Python | **82,825 行**（`backend/app` 171 文件；`moneyhelper` 包 8 文件） |
| 后端路由端点 | **338 个**，分布在 42 个 route 文件 |
| 数据层 | 29 个 db 模块、11,146 行，**全手写 aiosqlite SQL**（无 ORM） |
| 工具层 | 45 个 function-calling 工具 + deep 工具；schema 已由 pydantic 单一真源派生 |
| 前端 | 147 个 ts/tsx、**38,894 行**；17 个财务视图、49 个顶层组件、24 个设置分区 |
| 国际化 | zh.ts / en.ts 各 2,071 行（键唯一，无重复）；组件内**另有 427 行硬编码中文未走 i18n** |
| 测试 | 后端 1,758 项；前端 195 项；Playwright e2e 覆盖 16 个页面 |
| 重复函数体（AST 归一化） | 产品代码 **18 组**；其中 34 处是同一助手函数被复制 |

**关键结论**：这个项目的重复不是"从零手写轮子"，而是 **M1 拆分期的复制粘贴**
——拆分 `db.py` / `main.py` 时，小的助手函数被整段复制进各模块，随后各自漂移。
所以修复方式不是引入大框架，而是**收敛真源 + 加机器检查防复发**。

### 1. 时间戳助手：16 处重复 → 1 个模块

- **重复证据**：`_now()` 12 处（db/banking、broker_credentials、connect_deep、expenses、gl、

- **真实缺陷**：复制过程中漂移成两种格式 —— `%Y-%m-%dT%H:%M:%S`（6 处，无时区偏移）
  与 `.astimezone().isoformat()`（10 处，带 `+08:00`）。二者混写进同一列会让
  `ORDER BY created_at` 的字符串排序错位。
- **处置**：新增 `backend/app/timeutil.py`，提供 `now_str()` / `now_iso()` / `new_id()`；
  16 个文件改为 `from ..timeutil import now_str as _now`（**保持原有格式不变**，
  避免顺手改格式引发数据迁移问题）。格式统一列入待办（见 §四）。

### 10. 测试夹具：`_temp_db` 19 处、`client` 25 处 → 各 1 处

- **重复证据**：19 个测试文件各写一份 `async def _temp_db(temp_db): yield`（纯转发）；
  38 个测试文件各写一份 `client`，其中 25 份是同一段代码的复制
  （仅 `app` / `main.app` / 局部 import 三种写法差异）。
- **处置**：`conftest.py` 提供共享 `_temp_db` 与 `client`（`temp_db` + `main.app`，不触网）；
  25 个纯 `client` 与 19 个 `_temp_db` 定义删除。
- **保留**：13 个带 `monkeypatch` 的 `client` 留在各自文件（行情/MCP/LLM 补丁属该测试私有），
  就近覆盖 conftest 同名夹具 —— pytest 语义天然支持，不需要额外机制。
- **踩坑记录**：个别文件的 `@pytest.fixture(autouse=True)` 只属于 `_temp_db`，
  删函数时装饰器会"掉"到下一个夹具上（表现为 `@pytest.fixture` 应用两次、或把测试函数
  变成夹具而静默不收集）。删夹具必须连装饰器一起删，或用 autouse 转发夹具保住语义。
  另：`test_evaluate.py` 的 `_temp_db` 虽然步骤相同，换用共享版后 2 个断言失败，
  已保留其私有实现 —— **行为等价要靠测试证明，不能靠肉眼比对**。

### 11. 时间戳：不迁移数据，改为钉住「谁用哪个时钟」

- **先证伪再动手**：按 INSERT 语句统计全部写库模块，**25 张表里没有一张被两种格式同时写过**
  （`now_str` 无时区 → payments / expense_claims / gl_entries / org / procurement；
  `now_iso` 带 `+08:00` → 凭据 / 连接 / 调动 / 行情缓存 / 模拟盘 / 部门报表 / 长任务）。
  所以不存在“混存历史数据”需要清洗，原计划的 `scripts/migrate-timestamps.py` **不必写**。
- **真正的问题**是漂移没有护栏：任何新模块给老表写另一种格式，字符串比较与排序立刻出错。
- **处置**：`backend/tests/test_timestamp_policy.py` 把 12 个模块 → 时钟的映射钉死
  （断言 `module._now.__name__`、断言函数来自 `timeutil`、断言两种输出可区分）。
  改函数即测试红，强制改动者同时给出迁移方案。
- **为什么不统一成一个**：两个函数各自对应一批已有数据的表，单向改格式会让同一张表
  出现新旧两种字符串，等于人为制造混写。统一的前提是整表重写时间列 —— 那是数据迁移，
  不是去重。

### 12. 前端错误文案：132 处三元表达式 → `errMsg()`

- **重复证据**：`e instanceof Error ? e.message : String(e)` 在 **20 个文件**里出现 **132 次**，
  变量名漂移出 `e` / `err` / `ex` / `error` 四种写法；另有 4 处带自定义兜底文案。
- **代价不只是行数**：漏写 `.message` 的版本会把对象塞进 toast，渲染成 `[object Object]`，
  只在网络异常时才暴露 —— 属于"抄出来的隐蔽缺陷"。
- **处置**：`lib/utils.ts` 新增 `errMsg(e, fallback?)`，语义顺序
  Error.message → 非空字符串 → 调用方兜底文案 → `String()`；
  137 处调用点全量替换，`lib/utils.test.ts` 5 项用例锁定该顺序。
- **为什么并入 `utils.ts` 而不是单开 `lib/err.ts`**：47 个调用文件里 28 个本来就要
  `import { cn } from "@/lib/utils"`，单开模块等于多 28 行 import 和一个文件。
- **行数口径说明**：本批 `frontend/src` 为 **+206/−167（净 +39）**，增量全是 import 行，
  收益是"137 处 → 1 处定义"。这是唯一一个"净增行"的批次，已单独在验收记录里标注。

### 15. 结构等价函数：负债/订阅删除收成一份

用 AST 规范化（把变量名与常量统一成 `_`）做的结构克隆扫描，`app/` 里
「≥4 条语句、结构完全一致」的只有 9 组，其中 7 组是同名类方法对（`__call__` 等）
或「查一行」这类本来就该分开的薄函数。真正值得合并的一组：

`db/debts.py` 的 `delete_debt` / `delete_subscription` —— 逐字相同的 10 条语句，
只有表名与快照 kind 不同 → 收敛为 `_delete_by_name(table, kind, name)`。
表名只来自模块内常量，不参与请求拼接，无注入面。

### 16. 证券代码前缀：3 份手写实现 → `app/symbols.py`

- **重复证据**：`quotes._to_secid`、`quotes._to_sina`、`connect/quote_tencent.to_tencent`
  三份逐字相同的「6 位数字 + 首位判市场」规则，只在输出前缀上不同。
- **漂移后果**（不是洁癖问题）：腾讯版补了北交所（`4/8/9` 开头），另外两份没有 ——
  同一只北交所股票在「腾讯现价」有值、在「新浪备源」永远是 None，
  用户看到的是时有时无的行情。合并时把这个差异显式化：`to_sina` 对 `bj` 返回 None
  （新浪本身没有该市场行情，交给备源而不是编个错前缀）。
- **结构**：`market_of(symbol)` 只回答"哪个市场"，`to_sina/to_tencent/to_secid`
  各自只负责前缀格式。新增数据源只需多一个前缀函数。
- **守卫**：`tests/test_symbols.py` 17 项，覆盖沪/深/北/ETF/非法输入与各源一致性。

### 17. 简单移动均线：2 份实现 → 1 个带 `ndigits` 的参数

`calculations/_shared.sma` 与 `calculations/technical.sma` 差一行 —— 后者 `round(v, 4)`。
这不是谁写错，而是两个用途：指标卡片要固定 4 位小数（否则长序列的浮点尾数
会把 `12.340000000001` 直接画在卡片上），回测曲线要全精度（截断会累积到收益）。
合并为 `sma(values, window, ndigits=None)`：指标页传 `ndigits=4`，回测不传。

### 18. 实体增删改：6 个端点同一模板 → `routes/_crud.py`

- **重复证据**：`debts_subs.py`（负债 2 + 订阅 2）与 `goals.py`（目标 3）共 7 个端点，
  每个 18-20 行完全同构：取 name → 调 db → 记 provenance → 清缓存 → 返回；
  更新型多一步 before/after 双快照。
- **真实风险**：漏写 `invalidate_dashboard_cache()` 时接口照样 200，首页数字却停在旧值 ——
  "改完刷新没变化"是最难排查的一类缺陷。收进一个外壳后这个动作不可能漏。
- **处置**：`_crud.create_entity / update_entity / delete_entity`，端点退化成 3 行调用；
  快照仍取整行（撤销要靠 `INSERT OR REPLACE` 回滚，不能只记变更字段）；
  校验异常统一 400，其余交给全局异常处理。
- **不合并**：没有把路由本身做成工厂函数 —— FastAPI 用函数名生成 operationId，
  同名会冲突并污染 OpenAPI；保留薄包装是对的。

### 19. 新浪行情解析：2 份 → 1 份「按列取值」

`_sina_quotes`（现价，第 3 列）与 `_sina_prev_close`（昨收，第 2 列）是同一段
「建代码映射 → 批量请求 → GBK 解码 → 正则拆行 → 取第 N 列」抄了两遍，
差异只有列下标与长度下界（`<4` vs `<3`）—— 后者正是 off-by-one 的高发处。
合并为 `_sina_fields(symbols, field)`，长度判断统一成 `len(parts) <= field`，
两个原函数退化为一行转发。

### 20. 防复发：`scripts/check-duplicates.py`

机器检查三类问题，产品代码当前**全绿**：

1. 受管助手（`_now` / `_now_iso` / `_new_id` / `_bad` / `_err` / `_sma` / `_t`）只允许出现在真源模块；
2. 完全相同的函数体（≥3 行，AST 归一化）；
3. 前端 `DataKind` / `SectionId` 只允许一处定义。

默认跳过 `backend/tests`（测试夹具的重复另列待办）；`--include-tests` 可全量扫描。

## 八、补上"零操作"缺口的最后一段：自动建账 + 流水自动入账

浏览器打通"零输入出报表"之后，顺着链路往上追，发现两处**结构性缺口**——不解决，
"傻瓜式"就只是报表页上的一个按钮：

### 8.1 缺口一：系统没有默认科目表

`gl_accounts` 从来没有播种逻辑（`grep DEFAULT_ACCOUNTS` 为空）。新用户进总账是一张空表，
必须先自己懂"1001 银行存款 / 2202 应付账款"才能建账——这和"任何人不用专业能力"直接冲突。

**做法**：`app/calculations/chart.py` 收 18 个常用科目（资产 5 / 负债 4 / 权益 3 / 收入 2 / 费用 4），
`db.gl_bootstrap()` 幂等铺开（只补缺、绝不覆盖用户改过的科目，期间已存在就复用），
`POST /api/gl/bootstrap` 暴露给界面，总账页空态直接给「一键建账」按钮。

**为什么不在启动时自动播种**：项目里所有需要"科目 1001"的测试都是自己先建科目，
启动播种会让 `POST /api/gl/accounts` 撞唯一键，连带几十个用例失败；而且启动写库这件事
本身不可观测。改成"用户第一次看到空表时点一下"——一次点击即完成，仍然不需要任何会计知识。

### 8.2 缺口二：银行流水与总账之间没有桥

`bank_import_csv()` 只写 `bank_transactions`，凭证要靠 `payment` 才有
（`payments.gl_entry_id` 是付款侧）。家庭用户直接把银行 CSV 导进来，总账依然为空，
报表依然是 409。我此前在界面上写的"凭证由……银行流水自动生成"其实不成立，已同步修正文案。

**做法**：
- `bank_transactions` 加 `gl_entry_id`（走既有 `cols` 迁移，只加列不重建表），既是归属也是幂等标记；
- `bank_import_csv(auto_entry=True)`：导入后逐条按 `pick_account_code()` 规则生成草稿凭证
  （支出：借 6602/6603/6401、贷 银行；收入：借 银行、贷 6001/6051），跨月自动按年月建账；
- **单条失败只跳过该条**，不影响导入本身——流水是事实，凭证是可重建的派生物，
  这条原则也适用于后续所有"自动派生"功能。

- 总账页「新增凭证」手工表单（选科目/借方/贷方）收进 `Disclosure`，标题改为
  "手工录凭证（一般不用）"，首屏只留凭证列表；
- 流水导入提示追加「已自动生成 N 张草稿凭证」；

## 十一、连"建账"也不让用户点：from-gl 默认自动建账套

上一批把「一键建账」做成了总账页上的一个按钮——但那仍然是"要用户点一下"。
按定位（**人零操作、复杂交给系统**），这一步也不该由人触发。

**做法**：`POST /api/statements/from-gl` 增加 `auto_setup`（**默认 true**）。
没有会计期间时先 `gl_bootstrap()` 铺科目表与当期期间，然后：

| 情形 | 返回 | 文案 |
|---|---|---|
| 有已过账凭证 | 200 | 正常出表 |
| 只有草稿 | 409 | `系统已自动建好账套（N 个科目、Y年M月期间）· Y年M月有 K 张草稿凭证还没过账，无法出报表（可加 auto_post=true 由系统自动过账）` |
| 一条凭证都没有 | 409 | `系统已自动建好账套（…）· Y年M月还没有任何凭证：导入银行流水或记一笔就能出报表` |
| 显式 `auto_setup=false` | 409 | 沿用旧的"请先过账凭证"，不改变既有语义 |

**一条原则**：报错必须**同时给出下一步怎么做**（"导入银行流水或记一笔"），
不能只报"无法出报表"——用户不懂财务，不知道缺的是什么。

**界面**：错误态按钮文案从"帮我过账并出报表"改成"全部交给你，直接出报表"
（zh）/ "Just do it and give me the report"（en）——它现在同时覆盖建账与过账。

## 十二、科目表/期间不再各页各拉一份（useLedgerRefs）

**扫描**：`listGlAccounts()` 在总账、银行对账、报销、采购应付四个页面各调一次，
`listGlPeriods()` 在总账、银行对账各调一次；每个页面还各自维护一份
`accounts` / `periods` state、一份 `loading` 与一份 error toast。同一次页面切换里，
同一份科目表可能被请求 3–4 次。

**做法**：`lib/use-ledger-refs.ts` 用 TanStack Query 收口（`["gl","accounts"]` /
`["gl","periods"]`，`staleTime` 60s），对外暴露
`useLedgerRefs() → {accounts, periods, loading, error, invalidate}`。
改科目/期间的操作（建账、新增科目、新增期间、关账）之后调 `invalidate()`，各页不必互相知道。

**为什么用 TanStack Query 而不是手写模块级 Map**：这两份数据"很少变、到处用"，
缓存失效、并发去重、登出清理本来就是库的职责；手写一遍等于把库重做，还大概率漏掉失效时机。

**已迁完 4 个页面**（GlPage / ExpensesPage / ProcurementPage / BankPage）：

| 页面 | 迁移前每次进页的请求 | 迁移后 |
|---|---|---|
| 总账 | accounts + periods | 走缓存 |
| 报销 | claims + accounts | 只拉 claims |
| 采购应付 | vendors + orders + payables + accounts | 只拉前三样（合并成一次 `Promise.all`） |
| 银行对账 | payments + txns + claims + accounts + summary + periods + recons | 只拉前五样 + recons |

各页保留自己的 `loading` / 过滤逻辑（报销按 expense/credit 分两类、采购按应付/费用分两类），
只是数据来源换成共享查询——**过滤发生在渲染期，不在请求期**，所以不影响任何页面口径。

`tsc` 0 错 / vitest 205 全绿 / build 成功 / `pages-all`（17 页可达）+ 总账页截图与迁移前一致。

## 十三、16 处手写 `<table>` 收口到一个骨架组件（§五 第 8 条完成）

**扫描**：全项目 `<table>` 共 **16 处**（原估计 13 处），分布在 11 个文件：
`ConnectDeepPanels`(2)、`ConnectPage`、`DebtPayoffPage`、`EntryView`、`GlPage`、
`PaperTradingPage`(3)、`PositionsTable`、`ResearchPage`、`StatementsPage`、
`StrategyPage`(4)、`settings/AuditSection`。

容器 class 有 9 种组合（字号 11/12/13/14px、`table-fixed`、`min-w-[420|520|560px]`、
`border-collapse`、`text-left`），同一份"表格该长什么样"的知识被复制了 16 份。

**做法**：`components/ui/table.tsx` 只统一**容器层**：
`size(2xs=11px / xs=12px / sm=13px / md=14px)`、`fixed`、`collapse`、`minWidth`、`align`。

**刻意不做的**：不抽象成 `columns/rows` 配置式表格。各表的内边距、语义列（金额右对齐、
状态徽章、可排序表头）差异是真实存在的，配置化只会把一个 10 行表格写成 30 行配置，
反而更难维护。这次要消除的是"16 份容器 class"，不是"16 种业务表格"。

**等价性**：`collapse` 默认 **false**（原生默认 separate），只有原本显式写了
`border-collapse` 的 2 处（`DebtPayoffPage`、`PositionsTable`）才打开——不默认开启，
避免静默改变相邻边框的渲染。

**验收**：`tsc` 0 错 / vitest 205 全绿 / `vite build` 成功 / `pages-all` 17 页可达 /
17 页截图全部生成。**诚实说明**：截图里的几个页面（模拟盘、策略）当时无数据，
表格未渲染，所以"逐表视觉比对"实际上没有证据，只保证类名映射逐项等价。
若后续某表出现错位，优先怀疑 `minWidth` 与 `align` 的映射，而不是业务列。

### 顺带记录：这一项为什么之前被判为"暂缓"

原计划写"需视觉回归才能判断"。浏览器到位后发现真实障碍不是视觉，而是
**表格多数不在首屏/无数据时不渲染**——所以视觉回归只能覆盖一部分。
结论：这类"类名等价替换"应靠"映射表逐项对照 + tsc + 页面可达"，不必等满屏数据；
但**改结构**（合并列/改语义）仍然必须有数据才能验证，两者不能混为一谈。

## 十五、i18n 迁移（§五 第 6 条）：先做"键一致性"示范，批量留待下批

### 15.1 为什么不能批量脚本替换（这是关键结论）

`StatementsPage` / `ResearchPage` 里的中文有两类：

1. **纯展示文案**（标题、提示、按钮）——可以把字符串换成 `t("key")`，改了不会影响逻辑；
2. **ECharts 的键**：图例名同时是 `legend.data` 的元素、`series.name` 的值、`selected` 的键。
   这三处必须是**同一个字符串**。如果只把其中一处换成 `t()`、另一处留着中文，
   图例就会与系列对不上（图例点了没反应、或显示两个图例项）——**不报错，只是点不动**。

所以第 2 类不能"逐条替换"，必须"先取名、再引用"：在组件内定义
`const cfOp = t("stmt3.cfOperating")`，然后 `legend.data`、`series.name` 都引用 `cfOp`。
批量脚本无法知道哪些中文是键、哪些是文案，硬替换会制造一批"图例点不动"的隐性 bug。

### 15.2 本批完成的部分

现金流三流堆叠图（`CashflowStackChart`）——它是本项目"图例=系列键"最典型的一处
（`legend.data` 与 3 个 `series.name` 共 4 个硬编码中文必须同值）：

```tsx
const cfOp = t("stmt3.cfOperating");
const cfInv = t("stmt3.cfInvesting");
const cfFin = t("stmt3.cfFinancing");
legend: { …, data: [cfOp, cfInv, cfFin] },
series: [{ name: cfOp, … }, { name: cfInv, … }, { name: cfFin, … }]
```

新增 3 个 zh/en 键；i18n 守卫 345 → **339**（基线同步下调，棘轮不会回退）。
