# 4.24.0 归因托管

> 口径时间：2026-11-25。版本 `4.24.0`（上一版 `4.23.0` AI 托管台与电商经营测算）。

## 一、为什么先做这个

4.23.0 把税务交接和企业月结接进了托管台，但月结之前还有一段重复劳动：流水分类里堆着“其他/未分类”，归因页要逐条核对规则候选。分类不准，月结和税务包的数字就会带着噪音。

这轮不再加新的外部通道，只把已有的“规则候选 → 人工确认”收成第三个托管动作：`attribution_confirm`。它发生在月结之前，只改流水分类，不改金额、日期和余额，且每次都可回滚。

## 二、动作契约

- 动作键：`attribution_confirm`；默认 `manual`，沿用 `manual / assist / auto` 三档。
- 范围：只扫当前账期（`YYYY-MM`），候选来自 4.17.1/4.17.3 的规则引擎与自定义规则。
- 只自动确认 `custom_rule` 与 `rule` 两类来源；`history` 同类即使置信度较高也不自动确认，避免“同一商户、不同用途”被历史带偏。
- 默认最低置信度 `0.7`，默认本批合计上限 `10000` 元；`0` 表示不设金额上限。
- 单次最多确认 100 条；超过 100 条的部分不静默丢弃，计划里返回 `pending` / `skipped` 供下一轮继续。
- 本批待确认金额合计超过上限时，`auto` 也回落 `awaiting`，必须再确认一次。
- 执行走 `batch_apply_confirmations`：单事务原子写，分类在计划后若被改动会整批拒绝；每条写 `attribution_confirmations` 快照，并追加 `record_provenance` 证据。
- `run-all` 顺序改为：归因确认 → 企业月结 → 税务交接。归因先做，月结和税务包读到的是确认后的分类。

## 三、前端

- 托管台从两张动作卡扩到三张：归因、税务、月结。桌面端三列，移动端单列。
- 归因卡可配“本批合计上限”和“最低置信度”，切模式即保存，切模式不丢未保存的阈值。
- 结果区区分：手动只出计划、候选金额/笔数、已确认笔数、超阈值待确认、无候选阻断、执行失败。
- 中英文案同步；页面边界补上“归因”，不再只写投递与月结。

## 五、本轮不做

- 发票批量入账尚未接总账科目映射，先把发票台账与凭证规则设计清楚，再进托管。
- 平台账单对账需要先把各平台导出格式、商户授权与文件收件箱定下来，不能拿一个上传预览冒充自动对账。
- 订阅续费提醒仍由既有调度巡检负责，暂不包装成托管动作。
- 税局申报、银行划款、法定合并、社区代发布仍受资质/授权约束，不进入本轮“已完成”。
