**一句话结论**：现在是一个可运行、可审计、数字可复核，财税时序、可配置归因、调度告警、企业多主体合并、外部交接包与真实投递通道都有真实数据源或真实出站动作的财务系统；资料包生成后能留档、能确认线下交接、能比对来源摘要，也能通过用户自备 SMTP 真发信，或通过签名 HTTPS 网关真 POST 给服务商。它不是“全税种自动申报平台”，也不是法定合并报表系统；投递回执的 `accepted` 只代表对端受理，不是税局申报成功、银行付款成功或审计意见。外部动作仍受税局资质、持牌通道与接口准入约束，不能靠代码单方面宣称完成。

## 二、已交付功能清单

### 本轮外部投递通道（4.22.0）

- 两张新表：`external_channels` 存通道配置、启用状态、上次测试结果；`external_deliveries` 存投递幂等键、状态、收件人、请求摘要与回执。密钥只进 vault，列表不回显。
- 四类通道：`smtp`（税务/付款/合并）、`tax_gateway`（税务）、`bank_gateway`（付款）、`audit_gateway`（合并）。
- 真实动作：SMTP 用 `smtplib` 真发信，附包体 JSON、SHA256 摘要与付款 CSV；网关用 `httpx` 签名 POST，带时间戳、HMAC-SHA256 签名与幂等键。
- 安全默认：外部邮箱必须 STARTTLS/SSL；外部网关只允许 HTTPS；内网/保留地址默认拒绝；本机明文或 HTTP 联调需 `MH_ALLOW_LOCAL_CHANNELS=1`；无密钥、未启用、缺地址时 fail-closed。
- 投递规则：只把 2xx 视为受理；同一底稿重复点击返回 `duplicate`；成功自动进入交接台账，失败写 `HANDOFF_SEND_FAIL` 审计。
- 前端：四张通道卡、配置侧栏、二次确认投递、最近投递与台账投递徽章；中英文案补齐约 80 个键。
- 真实验收：本地 SMTP `127.0.0.1:2525` 真收测试邮件与业务邮件；本地 HTTP `127.0.0.1:9099/hook` 收到签名 POST 并返回 `SINK-RECEIPT-4220`；两类通道各完成一次真实投递，状态 `accepted` 并留痕。
- 边界：`accepted` 只代表对端受理，不代表税局申报成功、银行付款成功或审计意见；税局直连仍需乐企准入，资金划转仍需持牌通道，法定合并仍需审计口径，社区代发布仍需平台授权。截图 `192`–`198`。

### 上一轮交接留档与线下确认（4.21.0）

- 交接台账：`GET /api/external/handoffs`，合并 `HANDOFF` 与 `HANDOFF_ACK` 审计事件；返回总数、仅留档、已交接与边界说明。
- 留档：`POST /api/external/handoffs`，按类型与期间生成包并追加 `HANDOFF`；同 `packet_id` 幂等，重复调用 `created=false`。
- 线下确认：`POST /api/external/handoffs/ack`，只允许已留档的包转为 `handed_over`；未留档 404，重复确认 `updated=false`。
- 来源摘要：三类包统一带 32 位 `source_hash`，覆盖包体除生成时间与摘要本身外的全部字段；台账与当前同 `packet_id` 包比对并显示一致/不一致。
- 存储：不新增表、不写迁移；`detail` 存 JSON 并受审计函数 500 字符截断，备注限 120 字。
- 前端：三卡「留档」按钮、底部交接台账、操作备注、确认按钮、计数徽标与亮暗主题；截图 `181`–`183`。

### 上一轮外部协同前置层（4.20.0）

- 前端「账务 → 外部协同」页签；三包状态徽标、勾稽、明细、边界与亮暗主题。

### 个人侧

- 一句话记账与多笔拆分；微信/支付宝/银行 CSV/PDF/发票二维码/OCR 导入。
- 持仓、净值、集中度、再平衡、定投、回测、月度报告。
- 订阅识别与到期提醒、异常扣款识别、现金流三档预测。
- 财务健康五维评分（储蓄率、DTI、应急金、集中度、多样性）。
- 长期任务：阶段契约、检查点回滚、差异化下游过期、运行中工具进度。
- 收支归因：规则表 + 账本历史给候选，展示规则 id/命中词/置信度；确认后才写回分类，并记录 before/after 与依据。
- 归因规则可配置：自定义关键词、分类、方向、优先级；批量确认最多 100 条原子写；最近确认可逐笔撤销，撤销证据保留。

### 企业侧

- 复式总账：科目表、期间、日记账、草稿→过账→冲销、试算平衡、期间锁。
- 报销申请与“申请人≠审批人”；采购到付款：供应商→采购单→应付→付款，逐步生成凭证。
- 银行对账：账户/金额/方向匹配、账实差额、签核门槛。
- 财报分析：三表输入、比率、杜邦、预警、报告文本；报表快照存取。
- 税务计算：增值税、企业所得税、个税、工资、综合税负、月结 12 项清单。
- 月末自动结账：先过账草稿再关账；已关账幂等；无期间静默跳过。
- 财税时序：按月聚合已过账凭证的收入、费用、利润、现金流入流出、税费计提/缴纳与凭证数；缺账月份返回 `missing`，不拿 0 冒充已结账。
- 多主体管理合并：集团范围、`full` 100% 全额纳入、`proportional` 按持股折算、人工抵销分录、合并三表与科目底稿；缺期间/无过账主体显式排除；不做 NCI、权益法、法定合并。

- APScheduler 真实定时任务；4.17.0 增加 `automation_runs` 台账、同工作流串行锁、幂等键、手动补跑；4.17.1 的时序与归因均按租户隔离，候选只读扫描最近 800 笔流水。

- 4.17.3 归因控制面：自定义规则融合候选、批量确认单事务、误判回滚仅在分类未被二次改动时生效，规则采纳/回滚统计与确认列表同源。

### P2：受外部资质约束，不能默认交付

1. 税局直连申报/缴款：需要“乐企”准入（营业收入、开票量、纳税信用等门槛）或服务商通道；当前没有资质，不能实现。4.22.0 已留签名 HTTPS 适配器，资质到位后填地址与密钥即可真实投递，但不生成申报结论。
2. 银行/券商真实资金划转：需要持牌通道与用户授权；默认只做 handoff，不自动划款。4.22.0 已留银行网关适配器，实际划款仍需持牌方回执。
3. 集团法定合并报表：需要审计口径、抵消分录与合并范围确认；当前只做管理分析。4.22.0 已留审计交接网关，不等于审计意见。
4. 五个内容社区“上线”：需要各平台账号、登录与发布授权；未获授权前只能准备素材，不能代发。

## 六、同步机制

1. 每次版本提交前：`git fetch` + `git ls-remote` 核对五远端 `main`，以远端 SHA 为准，不以推送命令的退出码为准。
2. 本文与 `CHANGELOG.md`、`docs/index.md`、`docs/index.zh.md`、版本文件同批更新。
3. 新增能力必须同时更新：已交付清单、待开发池、路线图、溯源表；四块缺一不算完成。
4. 文档里的每个“已交付”都必须能在仓库找到入口（路由/函数/测试），否则降级为“待开发”。
