## 一、当前核心状态

| 维度 | 事实 |
| --- | --- |
| 产品定位 | 本地优先的个人 + 小微企业财务部门：确定性计算内核负责数字，模型只负责措辞 |
| 技术栈 | FastAPI + SQLite（aiosqlite）+ APScheduler；React 19 + Vite + ECharts；LiteLLM |
| 代码规模 | `backend/app` 521 个 Python 文件；`frontend/src` 245 个 TS/TSX 文件；63 张表；381 个路由声明 |
| 测试基线 | 后端 1930 项通过（4.17.1 全量，267.53s）；前端 243 项通过；`tsc` 与 `build` 通过 |
| 运行方式 | `http://127.0.0.1:8099`；数据落本地 SQLite，无云端遥测 |
| 模型状态 | 当前配置 `glm-5.3-flash`；模型只做自然语言表达，不参与金额计算 |
| 自动化现状 | APScheduler 已有晨报、订阅巡检、连接源每小时同步、账单收件箱每 10 分钟扫描、每月 1 日 02:00 月结；4.17.0 新增运行台账与手动补跑；4.17.1 财税时序只读已过账凭证，归因候选不落库直到人工确认 |
| 财税现状 | 增值税/企业所得税/个税/工资/税负测算/月结清单/财报分析已落地；4.17.1 新增按月财税时序（收入/费用/利润/现金/税费，缺账显式标记）与收支归因候选/确认；**未接入税局直连，不代用户申报、缴款** |
| 多主体现状 | 已有租户、部门、成员、总账期间与多用户隔离；集团合并报表仍是分析口径，不是法定合并 |
| 安全边界 | 本地优先；写操作审计、备份恢复只回偏好；远程控制用一次性令牌；敏感财税数据不交给第三方子智能体 |
| 自动化台账 | `automation_runs` 记录工作流/触发/步骤/耗时/错误；同进程串行、幂等键、每租户保留 200 条 |

**一句话结论**：现在是一个可运行、可审计、数字可复核，且财税时序与归因都有真实数据源的财务系统；不是“全税种自动申报平台”。后者受税局资质与接口准入约束，不能靠代码单方面宣称完成。

## 二、已交付功能清单

### 个人侧

- 一句话记账与多笔拆分；微信/支付宝/银行 CSV/PDF/发票二维码/OCR 导入。
- 持仓、净值、集中度、再平衡、定投、回测、月度报告。
- 订阅识别与到期提醒、异常扣款识别、现金流三档预测。
- 财务健康五维评分（储蓄率、DTI、应急金、集中度、多样性）。
- 长期任务：阶段契约、检查点回滚、差异化下游过期、运行中工具进度。
- 收支归因：规则表 + 账本历史给候选，展示规则 id/命中词/置信度；确认后才写回分类，并记录 before/after 与依据。

### 企业侧

- 复式总账：科目表、期间、日记账、草稿→过账→冲销、试算平衡、期间锁。
- 报销申请与“申请人≠审批人”；采购到付款：供应商→采购单→应付→付款，逐步生成凭证。
- 银行对账：账户/金额/方向匹配、账实差额、签核门槛。
- 财报分析：三表输入、比率、杜邦、预警、报告文本；报表快照存取。
- 税务计算：增值税、企业所得税、个税、工资、综合税负、月结 12 项清单。
- 月末自动结账：先过账草稿再关账；已关账幂等；无期间静默跳过。
- 财税时序：按月聚合已过账凭证的收入、费用、利润、现金流入流出、税费计提/缴纳与凭证数；缺账月份返回 `missing`，不拿 0 冒充已结账。

### 自动化与开放能力

- APScheduler 真实定时任务；4.17.0 增加 `automation_runs` 台账、同工作流串行锁、幂等键、手动补跑；4.17.1 的时序与归因均按租户隔离，候选只读扫描最近 800 笔流水。
- MCP Server 暴露账本/分析/行情等能力；远程控制手机端可操作同一实例。
- 五远端同步：GitCode、GitHub（badhope / Morningstar202604 / X33834）、Gitee。

## 三、待开发任务池

按“能真实交付”的顺序排，不按口号排。已完成项只留结论，不再重复排期。

### 已收口（4.17.0 / 4.17.1）

1. 四模块基线文档与远程 `main` 对齐，开源与大模型能力逐项标注“已复用 / 仅参考 / 未接入”。
2. 自动化运行台账接入月结与手动补跑，后端/前端测试覆盖。
3. 真实压测：个人千万级资产、企业 100 主体计税、10 租户 × 12 期间 × 2,400 张凭证、32 并发流水；结果见 `docs/STRESS-4.17.0.md`。
4. 财税时序看板：只读已过账凭证，缺账显式标记，前端柱线组合与明细表同源。
5. 收支归因：规则 + 历史候选、人工确认、确认留痕；无命中不编分类。
6. 代码合规扫描：本轮新增代码过 ruff；`check-duplicates.py` 仍剩 5 处存量助手重复（remote / shares / thread_context / longtask / personal_review），不能为过扫描改返回类型。

### P0：下一轮必须收口

1. 任务重试/死信/告警：失败步骤指数退避、死信队列、站内告警；不做“假装成功”。
2. 进程停机补偿：启动时识别错过窗口的任务，按幂等键补跑或显式标记 `missed`，当前只做到重注册。

### P1：平台能力补全

1. 归因规则可配置与批量确认：规则阈值、同商户记忆、批量确认都要有审计与撤回路径。
2. 个人资产调优建议：只输出可解释的候选动作与风险，不代下单。
3. 财税时序下钻：从月度汇总进到凭证/发票明细，保留期间锁与已过账口径。

### P2：受外部资质约束，不能默认交付

1. 税局直连申报/缴款：需要“乐企”准入（营业收入、开票量、纳税信用等门槛）或服务商通道；当前没有资质，不能实现。
2. 银行/券商真实资金划转：需要持牌通道与用户授权；默认只做 handoff，不自动划款。
3. 集团法定合并报表：需要审计口径、抵消分录与合并范围确认；当前只做管理分析。
4. 五个内容社区“上线”：需要各平台账号、登录与发布授权；未获授权前只能准备素材，不能代发。

> 结论：标“参考”的不等于“已复用”。任何第三方能力进入核心财政链路前，必须先有适配层、测试和回滚路径。

## 六、同步机制

1. 每次版本提交前：`git fetch` + `git ls-remote` 核对五远端 `main`，以远端 SHA 为准，不以推送命令的退出码为准。
2. 本文与 `CHANGELOG.md`、`docs/index.md`、`docs/index.zh.md`、版本文件同批更新。
3. 新增能力必须同时更新：已交付清单、待开发池、路线图、溯源表；四块缺一不算完成。
4. 文档里的每个“已交付”都必须能在仓库找到入口（路由/函数/测试），否则降级为“待开发”。
