# Moneyhelper 项目基线（4.17.0）

> 口径时间：2026-11-24。基线提交：`d48d723`（4.16.49，远程 `main` 已核验一致）。
> 本文是团队协作的唯一基准锚点：状态、已交付、待开发、路线图四块一律以仓库当前代码为准；未落地的能力只进“待开发任务池”，不提前写成“已交付”。

## 一、当前核心状态

| 维度 | 事实 |
| --- | --- |
| 产品定位 | 本地优先的个人 + 小微企业财务部门：确定性计算内核负责数字，模型只负责措辞 |
| 技术栈 | FastAPI + SQLite（aiosqlite）+ APScheduler；React 19 + Vite + ECharts；LiteLLM |
| 代码规模 | `backend/app` 517 个 Python 文件；`frontend/src` 243 个 TS/TSX 文件；62 张表；378 个路由声明 |
| 测试基线 | 后端 1922 项通过（4.16.49 全量，250.16s）；前端 243 项通过；`tsc` 与 `build` 通过 |
| 运行方式 | `http://127.0.0.1:8099`；数据落本地 SQLite，无云端遥测 |
| 模型状态 | 当前配置 `glm-5.3-flash`；模型只做自然语言表达，不参与金额计算 |
| 自动化现状 | APScheduler 已有晨报、订阅巡检、连接源每小时同步、账单收件箱每 10 分钟扫描、每月 1 日 02:00 月结；4.17.0 新增运行台账与手动补跑 |
| 财税现状 | 增值税/企业所得税/个税/工资/税负测算/月结清单/财报分析已落地；**未接入税局直连，不代用户申报、缴款** |
| 多主体现状 | 已有租户、部门、成员、总账期间与多用户隔离；集团合并报表仍是分析口径，不是法定合并 |
| 安全边界 | 本地优先；写操作审计、备份恢复只回偏好；远程控制用一次性令牌；敏感财税数据不交给第三方子智能体 |
| 自动化台账 | `automation_runs` 记录工作流/触发/步骤/耗时/错误；同进程串行、幂等键、每租户保留 200 条 |

**一句话结论**：现在是一个可运行、可审计、数字可复核的财务系统；不是“全税种自动申报平台”。后者受税局资质与接口准入约束，不能靠代码单方面宣称完成。

## 二、已交付功能清单

### 个人侧

- 一句话记账与多笔拆分；微信/支付宝/银行 CSV/PDF/发票二维码/OCR 导入。
- 持仓、净值、集中度、再平衡、定投、回测、月度报告。
- 订阅识别与到期提醒、异常扣款识别、现金流三档预测。
- 财务健康五维评分（储蓄率、DTI、应急金、集中度、多样性）。
- 长期任务：阶段契约、检查点回滚、差异化下游过期、运行中工具进度。

### 企业侧

- 复式总账：科目表、期间、日记账、草稿→过账→冲销、试算平衡、期间锁。
- 报销申请与“申请人≠审批人”；采购到付款：供应商→采购单→应付→付款，逐步生成凭证。
- 银行对账：账户/金额/方向匹配、账实差额、签核门槛。
- 财报分析：三表输入、比率、杜邦、预警、报告文本；报表快照存取。
- 税务计算：增值税、企业所得税、个税、工资、综合税负、月结 12 项清单。
- 月末自动结账：先过账草稿再关账；已关账幂等；无期间静默跳过。

### 自动化与开放能力

- APScheduler 真实定时任务；4.17.0 增加 `automation_runs` 台账、同工作流串行锁、幂等键、手动补跑。
- MCP Server 暴露账本/分析/行情等能力；远程控制手机端可操作同一实例。
- 五远端同步：GitCode、GitHub（badhope / Morningstar202604 / X33834）、Gitee。

## 三、待开发任务池

按“能真实交付”的顺序排，不按口号排。

### P0：本轮必须收口

1. 基线文档四模块与远程 `main` 对齐；开源能力与大模型能力逐项标注“已复用 / 仅参考 / 未接入”。
2. 自动化运行台账接入月结与手动补跑，补后端/前端测试。
3. 真实压测：个人千万级资产组合、企业多主体多期间总账的确定性计算与并发读写，出可复现脚本与结果。
4. 代码合规扫描：未使用导入、重复分支、超长函数、裸异常；只改有证据的缺陷，不为重构而重构。本轮新增代码已过 ruff，`check-duplicates.py` 仍剩 5 处存量助手重复（remote / shares / thread_context / longtask / personal_review），列入下一轮，不能为过扫描改返回类型。

### P1：平台能力补全

1. 企业财税时序看板：申报底稿、税负、现金流、期间状态统一到一条时间轴。
2. AI 收支归因：把“模型猜测”改成“规则候选 + 用户确认”，保留可追溯的归因来源。
3. 任务重试/死信/告警：失败步骤指数退避、死信队列、站内告警；不做“假装成功”。
4. 个人资产调优建议：只输出可解释的候选动作与风险，不代下单。

### P2：受外部资质约束，不能默认交付

1. 税局直连申报/缴款：需要“乐企”准入（营业收入、开票量、纳税信用等门槛）或服务商通道；当前没有资质，不能实现。
2. 银行/券商真实资金划转：需要持牌通道与用户授权；默认只做 handoff，不自动划款。
3. 集团法定合并报表：需要审计口径、抵消分录与合并范围确认；当前只做管理分析。
4. 五个内容社区“上线”：需要各平台账号、登录与发布授权；未获授权前只能准备素材，不能代发。

## 六、同步机制

1. 每次版本提交前：`git fetch` + `git ls-remote` 核对五远端 `main`，以远端 SHA 为准，不以推送命令的退出码为准。
2. 本文与 `CHANGELOG.md`、`docs/index.md`、`docs/index.zh.md`、版本文件同批更新。
3. 新增能力必须同时更新：已交付清单、待开发池、路线图、溯源表；四块缺一不算完成。
4. 文档里的每个“已交付”都必须能在仓库找到入口（路由/函数/测试），否则降级为“待开发”。
